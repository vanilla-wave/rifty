# Traps — hard-won gotchas (agents + humans). One entry = symptom → cause → rule.

## Worktrees & git

- **worktree-absolute-paths**: Write/Edit with main-checkout absolute paths silently lands in the main repo → worktrees share object DB so Read works, Write hits wrong tree → root every path at the worktree; tell subagents the worktree root; after edits `git -C <main-repo> status` must show none of your changes.
- **worktree-stale-main-diff**: `git diff main...HEAD` over-scopes a PR (invents huge surface) → local `main` ref lags origin → pin base via `git merge-base origin/main <branch>`; authoritative surface = `gh pr view --json changedFiles,additions`.
- **worktree-pinned-stale-reads**: Read/grep return outdated code → worktree pinned to old commit while origin/main moved → before analyzing "current main" compare HEAD vs origin/main; read via `git show origin/main:<path>` or re-branch from origin/main.
- **isogit-tag-not-peeled**: annotated-tag checkout/reset corrupts ref graph (child commit gets tag-object parent) → iso-git `resolveRef` returns UNPEELED tag oid, `checkout`/`writeRef` write it raw → peel via `readCommit`/`readObject` (type `tag` → peeled oid) before any ref write or `^0`/`~0`.
- **bare-repo-head-default-branch**: `git init --bare` + push `main` green locally, CI clone "Could not find HEAD" → CI `init.defaultBranch` unset → HEAD→master dangling → always `git init --bare -b main`.
- **rebase-changelog-union**: long playground rebase stops on CHANGELOG.md every commit → each commit prepends same `[Unreleased]` region → pre-register `apps/playground/CHANGELOG.md merge=union` in `$(git rev-parse --git-common-dir)/info/attributes`; verify top after (union can interleave).
- **rebase-main-origin-spec-sweep**: CI reddens after rebase pulls a new main-origin spec hardcoding what your branch renamed → grep ALL test dirs (incl `tests/e2e-prod`) for renamed/removed symbols after any rebase/merge with main.
- **squash-before-big-rebase**: incremental rebase over a main that landed a big feature re-conflicts the same regions per commit → `git reset --soft $(git merge-base HEAD origin/main)`, one commit, single rebase pass; semantic-reconcile the incoming feature to your renames, typecheck pinpoints the rest.
- **merge-adr-number-collision**: `refs:check` "duplicate ADR number" after merging main → both branches took the same next number → renumber YOURS everywhere (title, adr README row, code comments, CHANGELOG, e2e specs); grep repo-wide `ADR-NNNN`.
- **merge-duplicate-class-member**: both sides touched one class → git silently keeps BOTH method defs (no conflict marker), later def shadows the fix → after merge grep duplicate method names in touched classes; keep main's version.
- **merge-stale-compat-tests**: main-origin compat/App tests assert the ❌ your branch turned ✅ → updating them to new reality is correct; re-scan main-origin specs asserting superseded state.
- **rerere-silent-hunk-drop**: rerere with shared rr-cache can produce a merge missing an entire wiring block — no markers, builds fine → after ANY merge, `git grep` the key new symbols from both sides.
- **gh-merge-delete-branch-worktree**: `gh pr merge --delete-branch` from a worktree errors "'main' is already used by worktree" → only gh's local cleanup failed, the merge LANDED → verify `state=MERGED`, never re-merge; `git push origin --delete <branch>` manually.
- **git-add-batch-abort**: pushed commit missing files though gates were green → `git add a b c` stages NOTHING if one pathspec is fatal (e.g. just-rm'd path) → never re-add a removed path in the same batch; after commit `git status --porcelain` must be clean.
- **git-add-A-agent-junk**: `git add -A` after subagent workflows commits junk dirs (relative-path fs probes land in worktree root) → stage scoped paths; `git clean -nd` before staging.

## PR / CI verification

- **lint-includes-format**: local "lint passed" fails CI on formatting → `pnpm lint` = `biome check .` (format too) → `npx biome check --write <changed>` then re-lint.
- **chained-exit-masks-failure**: `cmdA ; cmdB` reports only cmdB's exit → run lint/typecheck/tests as separate commands, check each exit.
- **tsbuildinfo-false-green**: typecheck green locally, CI tsc red → stale `.tsbuildinfo`; vitest type-strips, so a fake missing a new interface method passes tests → when extending an interface, grep ALL implementations/stubs.
- **refs-check-docs-prefix**: dangling cross-refs pass CI → refs:check lints only citations with literal `docs/` prefix; ADR globs resolve only with the area subdir (`docs/adr/<area>/NNNN-*`) → write refs with `docs/` prefix or `ADR-NNNN` form; when deleting a doc, grep the bare-path form too.
- **compat-matrix-half-generated**: hand edits to generated compat `.md`s/README vanish → `compat:generate` renders them from cli.js inventories → edit cli.js rows, not the `.md`; after generate, diff README + sibling `.md`s for unintended reverts.
- **build-libs-dirty-sw**: `build:libs` dirties the tree with a big `apps/playground/public/sw.js` diff → it regenerates the committed artifact from current sources (stale on main) → confirm none of your symbols in the diff, `git checkout HEAD --` it; re-revert after each build.
- **red-main-fails-green-pr**: green PR fails CI on files you never touched → CI checks the PR merged into current origin/main → reproduce on a temp worktree of bare origin/main; carry a minimal "unbreak main" commit in your PR.
- **ci-only-fail-merge-worktree-first**: "fails only in CI, green locally" → failing spec may exist ONLY in main (CI tests the merge) → FIRST build a merge worktree (`git worktree add /tmp/x HEAD --detach && git -C /tmp/x merge origin/main`) and run specs there; throttling hypotheses later.
- **playwright-host-image**: every e2e/browser-unit/no-COI job dies in ~25 s at `playwright install --with-deps chromium`, "Playwright does not support chromium on ubuntu26.04-x64" → `ubuntu-latest` moved to 26.04 and the idle-expired browser cache forced the install; locked Playwright 1.60 has no 26.04 build; unit's agent-bench lifecycle tests also launch the Chromium the root postinstall downloads (`PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD` does not stop that CLI) → every CI job pins `ubuntu-24.04`, browser cache key carries `$ImageOS`; an image move rides a Playwright bump (`backlog/toolchain-build/playwright-ubuntu-26-runner-image`).
- **ci-cancelled-vs-timeout**: `if: always()` gate sat "queued" in runs a newer push cancelled (up to 124 min) → `always()` runs even in a cancelled run → gate uses `if: ${{ !cancelled() }}`, false only for a run-level cancel (superseded push, Cancel button): gate concludes `cancelled`, no runner. A dependency that times out concludes `cancelled` and flips the RUN conclusion to `cancelled`, yet `cancelled()` stays false and the gate runs red (PR #442 run 45411103440) → read the gate's verdict, not the run conclusion; never `cancelled()`/`failure()` alone to catch a timed-out job. Fallout: (1) a head run cancelled whole leaves every check `cancelled` and `gh pr checks` exits 0 (gh 2.98 exits non-zero only on fail/pending; text prints `fail`, `--json bucket` says `cancel`; PR #442 2026-11-24) → judge merge by states, never by exit code; (2) re-running an OLD run of a PR joins group `ci-pr-<N>` and cancels the head run within seconds (PR #442 run 45411638780 attempt 3) → never re-run a superseded run; re-run the head run.
- **ci-draft-light-run**: code-affecting draft PR shows `CI gate` red ("draft PR: heavy lanes withheld") → by design (ADR-0323 correction 2026-11-24): draft skips the heavy lanes, a skipped/green gate would read as merge-ready → mark ready for review (fires the full run); the red is not a bug; right after ready `gh pr checks` still shows that draft-era red gate until the full run reaches its gate (the gate check run is created only then; PR #446) → wait for the new gate, fail-closed meanwhile. Heavy `if` reads the event payload snapshot: a re-run of a draft-era run stays light after ready AND joins `ci-pr-<N>`, cancelling the live full run (see ci-cancelled-vs-timeout (2)); a draft-era `synchronize` queued after `ready_for_review` likewise supersedes the full run, leaving the head light/red (fail-closed, never false green) → need a fresh ready run on the current SHA: `gh pr ready --undo && gh pr ready` or a new push; never re-run a draft-era run. `gh pr checks --watch --fail-fast` right after ready exits on the stale red gate → wait for the new run by head SHA/`createdAt`. After draft→ready the rollup keeps `skipping` rows for the unexpanded matrix parents (`unit-and-conformance`, `e2e-chromium`) from the draft run beside the children's `pass` → read the verdict from `CI gate`. Branch protection and the `main` ruleset are disabled (2026-11-24): merge readiness rests on the DoD bucket read alone.
- **automerge-no-required-checks**: `gh pr merge --auto` merges instantly → main has no required status checks → never `--auto`: merge only on a green PR CI at HEAD; local `pnpm pr:check` is diff-scoped and runs no e2e.
- **stale-pr-merge-ref**: PR CI keeps testing against an old base after `main` moved → `refs/pull/N/merge` refreshes on `synchronize`; close/reopen can reuse a stale ref (#366 reopened after #365 landed still ran against the old base) → push a new commit (empty is enough) to pick up a base fix.
- **prod-e2e-separate-gate**: prod-only owner-boot regression passes pr:check + dev e2e + unit/parity → `test:e2e:prod` (build+preview) is its own lane → run it for any owner-boot / worker-entry / env-read / chunk-graph change.
- **verify-committed-not-worktree**: gates prove the WORKING TREE, not the commit → uncommitted/unstaged edits keep gates green while the push misses files → re-run the decisive check on the committed state before push.
- **parity-runner-in-process**: parity cases run rifty builtins in-process in the Node host → `globalThis.process` is REAL Node; bare `Buffer`/`process`/`console`/`global` in a case is Node==Node tautology (false-green) → builtins resolving "the live process" must `instanceof NodeProcess` check; cases must `require('node:buffer')` etc. explicitly; RED-check by stashing `packages/`. Same for host platform objects: Node's `MessageChannel`, default `Error.prepareStackTrace`, rejection-task order — a Chromium divergence (`postMessage` returning `undefined`, no default hook) is invisible there → prove it in browser-unit against the live Node oracle.
- **parity-capture-bom**: a parity case whose stdout/stderr/http body starts with EF BB BF went red after a correct fix, and `node -e` stdio cases could not see an offset-0 BOM drop → capture decoders used the WHATWG default (strips one leading BOM): rifty-side `stdoutText`/http body only (false RED), node-cli-eval capture on both sides (false GREEN; mutant proof 2026-11-17) → harness captures keep it (`ignoreBOM: true`); the Node side still decodes default-mode chunks per chunk (`run-in-node.ts` `c.toString('utf8')`), so print code points for byte-exact claims.
- **parity-win32-alias**: rifty ships `path.win32 === posix` → never parity-test `path.win32.*` (real Node diverges).
- **vitest-oracle-agent-env**: Node-oracle `vitest run` drops passing file/test lines (PR #351 misread it as native reporter behavior) → std-env `isAgent` (`AI_AGENT`, `CLAUDECODE`/`CLAUDE_CODE`, `CODEX_SANDBOX`/`CODEX_THREAD_ID`, `CURSOR_AGENT`, `GEMINI_CLI`, `OPENCODE`, `REPL_ID`, …; std-env 4.2.0 under vitest 4.1.11) swaps the default reporter for `agent` = MinimalReporter, drops colors and watch → run oracles under `env -u <markers> -u NO_COLOR -u FORCE_COLOR -u CI`; reproduce the agent shape with `AI_AGENT=claude`.
- **oracle-npm-stale-packument**: Node-oracle `npm install` resolves an older `latest` than the registry (vite 8.2.2 vs live 8.3.0, 2026-09-23) → the local npm cache / configured mirror serves a stale packument → oracle installs use `--prefer-online` against the public registry and record the resolved version.
- **codex-sandbox-listen-eperm**: `pnpm pr:check` / playwright / `tsx` lanes die 3–4 min in with `listen EPERM …/tsx-501/*.pipe` or a loopback `listen` refusal, no failing test → the Codex `workspace-write` sandbox denies IPC pipes and local ports by construction (21 hits on #294, twice on 2026-09-03), and every retry then passes through an LLM guardian → run those lanes with `sandbox_permissions: require_escalated` from the FIRST attempt; never read their in-sandbox failure as a code failure. Optional: `~/.codex/rules` prefix rules for `pnpm pr:check` / `pnpm test:*` skip the guardian.

## e2e

- **late-fetch-interception**: Playwright route/unroute can stall CDP when a stock esbuild Worker is blocked in Atomics.wait. Enable interception before boot; retain a pass-through route while adding/removing later owner-script holds. Keep the original reload/storage assertions.

- **host-oracle-ephemeral-port**: a real-Node oracle child dies `listen EADDRINUSE` on Linux CI only → its fixed/pid-derived port (40000+) sits inside Linux's ephemeral range (32768–60999; macOS starts at 49152) where outbound sockets land → probe-bind the exact host/stack the child uses and stay below 32768 (`freeHostPortPair` in `tests/e2e/cli-report.spec.ts`).
- **stale-foreign-server-port**: e2e tests PRE-change code (phantom pass/fail) → `reuseExistingServer` grabbed a sibling worktree's dev server on default 5273 → always set a dedicated `RIFTY_PLAYGROUND_PORT`; `lsof -nP -iTCP:5273 -sTCP:LISTEN` when results look wrong.
- **pipe-masks-playwright-exit**: `playwright ... | grep | tail` returns tail's 0 → capture playwright's exit directly, never through a pipe.
- **project-first-boot**: `goto('/')` then expecting LIVE/`$ vite` hangs → cold boot shows the chooser, no auto-boot (only `?preset=` deep-link boots) → `pickStarter`/`selectPreset` first, or wait launcher visible + close it and use Terminal 1.
- **isvisible-doesnt-wait**: `locator.isVisible({timeout})` returns CURRENT state immediately → helpers no-op on a not-yet-open dialog → `expect(...).toBeVisible()` before acting.
- **shell-mounts-after-admission**: first action after `goto('/')` hits a 2s timeout on `open-launcher` (≥3 of 69 hosted CI runs) → App shell mounts only after Workbench admission; owner Worker boot is ~420 dev-server module requests AFTER `load` → `waitForProjectIndex` / `openLauncher` before touching the shell, never a fixed short deadline (incl. default 5s `expect`).
- **reload-must-relaunch-dev-server**: post-reload restore shows tree but empty console/no preview → dev server is a pty that dies with the page; restart hook is gated on a session id that's null after fresh reload → restore branch must re-root owner AND relaunch dev server (ADR-0148); reload e2e must assert livepill running + preview, not just file/tab survival.
- **selector-e2e-misses-css**: wholesale-missing component CSS passes selector e2e + code review → selectors don't render pixels → for UI changes take a real screenshot and assert computed overlay geometry (fixed/centered), not selector presence.
- **force-click-silent-noop**: `click({force:true})` on a covered element dispatches into the overlaying layer = silent no-op (hang); without force = loud actionability error naming the coverer → never force-click buttons/menu items in e2e.
- **cross-file-contention-flake**: raising e2e workers re-flakes even with `describe.serial` → cause is CROSS-FILE contention (concurrent Vite-WASI cold-boots starve the owner worker: zero output, owner-RPC timeouts), not intra-file parallelism → heavy and light lanes must never overlap; a serialized lane runs long — don't mistake it for a hang; repro locally by oversubscribing `--workers`.
- **fix-flake-before-parallelizing**: shard/worker speedups lose → flake cost = readiness-timeout × retries dominates wall-clock variance, and sharding concentrates flaky specs into one inflated shard → fix the flake first; don't re-propose shards/`--workers` before that.
- **rejected-e2e-speedup-levers**: HAR/route WASM caching drops COOP/COEP → SAB undefined → green-but-broken; worker-scoped warm page dies under retries; in-page soft-reset breaks the reload contract; prebuilt V8 cache is per-context → don't re-propose these.
- **opfs-wipe-parallel-race**: owner/OPFS specs wiping per-origin storage can kill each other under fullyParallel CI → re-run the failed spec isolated (`--workers=1`) FIRST: isolated fail = real regression, isolated pass = the known race.
- **in-suite-fail-solo-pass**: heavy-lane spec fails in-suite, passes solo → contention, not the spec → run solo before "fixing" it.
- **sw-trace-body-crash**: Linux `sandbox-support` loses the whole browser in ~2 s, trace has only `test.trace` → inspect `DEBUG=pw:browser` for SIGTRAP; real HTTP 403 + trace HAR can call `Network.getResponseBody` after SW death (crbug 573662744). Browser-unit disables only SW network instrumentation; restore trigger: `backlog/toolchain-build/restore-service-worker-network-traces.md`. No timeout/retry fix.
- **dev-server-port-foreign-listener**: Playwright dies with "Timed out waiting 90000ms from config.webServer" though nothing of yours runs → a foreign listener (e.g. `tests/host/server.mjs` from another worktree) sits on the "dedicated" `RIFTY_PLAYGROUND_PORT` and Vite `strictPort` never binds → `lsof -nP -iTCP:<port> -sTCP:LISTEN` before every lane; empty or pick a free port.
- **temp-edit-hmr-breaks-e2e**: an unrelated terminal e2e fails (`tests/e2e/cli-report.spec.ts:569` "terminal command marker missing") while you RED-probe → a temporary source edit during a running Vite dev-server lane (e2e / browser-unit) hot-reloads the page mid-test → never edit sources while a dev-server lane runs: probe in another worktree or between lanes; rerun the failed spec isolated before blaming it.
- **e2e-runs-locally**: belief that COI blocks local e2e is wrong → playground vite config ships COOP/COEP, browsers installed → `npx playwright test --project=chromium <spec>` is the fastest RED→GREEN loop for owner/shell behavior.

## Browser runtime & bundling

- **copied-asset-fingerprints**: Workbench `dist/assets` bundles the runtime; shared-chunk changes rename, add or drop the large TypeScript worker's leading `./chunk-HASH.js` imports. `check:esbuild-legacy-retirement` pins the worker minus those imports (esbuild form, built siblings, ≤2048 bytes), sibling hashes zeroed; the lexical compiler `chunk-YYL3CQII.js` stays whole-file (ADR-0391 §Corrections 2026-11-24) — a runtime edit needs no re-pin. Red on the worker = its own content changed (TypeScript, ts-language-service, worker entry, esbuild/build config): copy the pin printed in the violation, keep negative payload tests and packed-browser proof; no ADR line. Header-ceiling red = the admission rule's bound: raising it is an ADR-0391 line. "leading import not in the admitted form" = esbuild emitted a header line the rule lacks (or an unbuilt chunk): never re-pin it — extend the form in the gate. SW stays classic; Workers are ESM.
- **docs-only-pr-check-needs-dist**: `check:esbuild-legacy-retirement` reads `packages/*/dist`; the docs-only `pr:check` lane skips `build:libs`, so a fresh worktree fails with "emitted generated esbuild client count is 0" — environment, not source: run `pnpm build:libs` once, then re-run.

- **nested-worker-notice-drop**: `page.workers()` keeps a parent Worker (and every ancestor) forever after close, renderer threads grow, intermittent even isolated → Chromium drops a nested child's termination notice still queued when the parent realm starts shutdown (`terminate()` or a `close()` task) while busy; a child ended by the parent's own context destruction is safe → never `terminate()` nested Workers in a realm about to end; `control:kill-tree` `cascade` + `release()` (ADR-0548); repro: busy parent terminates child, page terminates parent.
- **nested-relay-quadratic-read**: a large `readFileSync` is ~46× slower in a grandchild than in a direct child (esbuild-wasm service under Vite: 6.9 s local, 17–29 s CI, every Vite start) → a child realm relaying its nested Workers' `fs.*` answered each 256 KiB chunk with a whole-file upstream read (N×N owner requests) → a VFS a relay serves implements `ChunkedReadSource` (forward head/chunk as one upstream request); a new wrapper without it silently falls back to the quadratic path (ADR-0365 correction).
- **worker-console-invisible**: worker-realm logs never reach page/Playwright console; BroadcastChannel is shimmed in workers → route diagnostics via `process.stdout.write`; an eval-crashed kernel worker shows only as `page.on('worker')` create→close ~0.1s apart (DOM `error`, no exit frame).
- **pre-entry-hook-lives-in-host**: refactoring runtime-js's install path silently breaks the browser → `setKernelPreEntryHook` is last-writer-wins and the playground `kernel-worker-entry.ts` registration is the one that runs (ADR-0157) → update the host hook with any shim refactor; failure = silent emnapi pthread crash, preview 503, only the SW-preview e2e catches it.
- **worker-entry-chunk-graph**: adding a kernel import to `runtime-js/worker-entry.ts` co-locates its side-effect into the kernel startup chunk → process globals install BEFORE the pre-entry seam publishes the spec → persistent empty-env clobber, prod-only → keep the env reads; prod e2e is the proof.
- **worker-entry-side-effect-realm**: a top-level `if (isWorkerRealm)` side-effect re-exported from a package index runs in EVERY consumer worker's realm → gate side-effects on a precise published signal (e.g. the wasi-guest spec key), never "am I in a worker".
- **prod-dual-copy-buffer**: prod-only `Buffer.isBuffer`/`instanceof` failures (etag TypeError) → each `?worker&url` bundle carries its own `@riftydev/io` copy; pre-entry `globalThis.Buffer` ≠ child `require('buffer')`; dev serves ONE module so it hides the class → `installBundleLocalBuffer()` per child realm; catch via `tests/e2e-prod` or grep the io marker per dist worker chunk.
- **io-treeshake-side-effect**: no-coi CI `Packed client bundle budgets` fails `SDK packaging failures` (`main`/`sw` io > 5120 B; local `pr:check` green) → a module-level statement in `@riftydev/io` (prototype assignment, `Object.defineProperty`) or a property-access argument to a `/* @__PURE__ */` call (`Writable.prototype._write`) keeps ~48 KB of streams in every bundle → put prototype setup inside the pure stream-constructor call as a thunk (`makeCallableStreamConstructor(…, () => ({ … }))`); measure: esbuild-bundle `export { createSandbox } from '@riftydev/sdk'` aliased to `packages/io/dist` and sum eager io bytes.
- **browser-only-cant-red-in-node**: browser-only contract failures (e.g. `getRandomValues` rejects SAB-backed views) can't RED-check in node vitest → mock the browser contract (throwing spy) or find a Node-reproducible proxy on the same code path.
- **napi-wasi-loader-flags**: napi-rs loader silently swallows the wasm32-wasi load error → set `NAPI_RS_FORCE_WASI`; emnapi needs a Node `global` alias; Vite 8 dropped `optimizeDeps.disabled` → use `noDiscovery: true`.
- **solid-server-runtime-in-vitest**: node vitest resolves solid-js to the SERVER runtime — `createEffect` is a permanent no-op → modules with internal effects silently never subscribe (test timeouts, works in browser) → orchestration modules own no effects: explicit attach/dispose, App binds with a one-line createEffect (ADR-0197).
- **signal-read-leaks-tracking**: a module method reading signals inside a caller's `createEffect` gets tracked → resubscribe storm (LIVE pill fine, preview fetch times out deterministically) → `untrack()` INSIDE any public method that reads signals; unit tests can't catch it (server runtime has no tracking) — only e2e does.
- **template-literal-cooked-escapes**: code shipped inside template literals (preset templates, injected scripts, shim bodies): `\d` cooks to `d` (write `\\d`), a backtick in an added comment TERMINATES the literal → check for the enclosing backtick before editing; run the test that EXECUTES the generated string.
- **pty-snapshot-stale-cwd**: page-side session cwd is `/` until the first `pty:exit` → recording a RUNNING command's context from `manager.snapshot()` lies (`cd / && vite`, exit 127) → thread the owner's `ctx.cwd` onto the owner→page frame and prefer `frame.cwd`.
- **guest-stream-proxy-wrappers**: in Node guest realms `===` against captured `ReadableStream.prototype` methods / reader constructors fails, `Function#toString` still prints native text, heap snapshot shows an extra `Response` per stream, `util.types.isProxy`-style checks disagree with the engine → `builtins/fetch/platform.ts` Proxy-wraps `ReadableStream.prototype.{getReader,cancel,pipeTo,pipeThrough,tee,values,@@asyncIterator}` + `ReadableStreamDefaultReader`/`ReadableStreamBYOBReader` constructors (each observed stream gets a native witness `Response` for the disturbed bit); `internal/proxy-identity.ts` replaces `globalThis.Proxy` (+ `Proxy.revocable`) so guest-created proxies are tracked and `isProxy` follows `proxyIdentity()`, not the engine → infrastructure proxies use `runtimeProxy`, never `new Proxy` (else they masquerade as guest proxies); stream debugging accounts for the platform wrappers (ADR-0541).
- **css-equal-specificity-dead-override**: an override block silently loses to a LATER equal-specificity block — dead from the day the later block was added → write two-class overrides (`.base.__variant`); diagnose geometry via `getComputedStyle` + `document.elementFromPoint`, not source CSS.

## Testing discipline

- **unit-green-masks-desync**: all phases unit-green, feature dead end-to-end → constant→dynamic refactors leave hardcoded stragglers that compile and unit-pass; App/owner integration isn't unit-testable → grep EVERY hardcode of the old value; the FULL e2e suite is the real gate.
- **default-timeout-load-flake**: red main after green PRs, failure ≈5000ms with NO assertion diff → real-Worker test hit vitest's default `it()` timeout under higher CI parallelism → explicit generous `it()` timeout; keep inner protocol bounds (e.g. `waitReplyAsync(2000)`) as the correctness guard.
- **count-ratchet-lossy**: count-only ratchet passes a same-count swap silently → a count is a lossy aggregate → carry an identity digest (hash of the sorted normalized-signature multiset) per allowlist entry.
- **write-ack-not-durable**: sleep barriers "proving" persistence lie → write-ack means applied to owner memory; the OPFS write-through drains behind it → prove durability with an acked flush IPC (durable-or-throw flush), never a timeout.
- **short-report-bound-setup**: OPFS fixture dies with `seed failed` on CI, passes everywhere else → a deliberately short `ioReportTimeoutMs` (held-phase probe) also judged ordinary setup/repair via `flush()`, which reports a slow-but-successful native commit as a provisional timeout → certify success with `settleOpfsSetup` (`fence()` then `flush()`); keep the short bound for held phases; sweep by "short bound + report-only success check", not by filename (#340 missed `opfs-structural-repair`).
- **opfs-file-readback-race**: polling `getFile().arrayBuffer()` while a native writable is closing can throw `NotReadableError` on Linux — a fresh File can become stale before its read → await the actual flush/close acknowledgement before acquiring the readback File.
- **timer-judges-unread-io**: a real-process test reds only under CPU load — a closed-channel worker reported `… after closing its result channel without a result` with its own `code 7`, a result already written reported `timeout` (distinct from a child that really outlives a grace: `signal SIGKILL` is then honest, and its test cues the exit inside the grace) → a Node loop turn runs due timers before it polls I/O; a consumer that was not scheduled finds its timer due and the child's frame/exit unread at once → where any exit read is the child's own (a grace), decide after one poll (`setTimeout` → `setImmediate`, `packages/isolate-host/src/pool.ts`); where the outcome depends on *when* the child sent it (a deadline), a poll admits late results too — that needs the child's send time (`backlog/distribution/isolate-host-starved-deadline-outcome`); reproduce by stalling the consumer synchronously at the timer and cueing the child (`tests/protocol.test.ts` `STARVED_AT_GRACE`, starved-consumer cases both ways), never by load.
- **wall-clock-assertion-under-load**: a test with a real process reds under load, green in isolation; the diff is a clock comparison or an elapsed-time bound → the bound assumed the machine schedules both reads/processes promptly → assert the event, not the time: bracket a clock value between reads taken before and after it (`guest-export.test.ts`), give a scenario whose own outcome is the point a deadline it cannot reach (`pool-faults.test.ts` interval churn: `timeoutMs` 2³¹−1, a harness bound reds a hang) and a smaller worker ceiling to reach the same path sooner; a property visible only below the delivery latency gets a deterministic twin at its owner on a fake clock at that owner's outer boundary (`host-bridge.test.ts` interval period), the real-oracle row stays; a time bound stays only where the time is the contract, with a stall injected at the judged point as its RED.

## Tooling wiring

- **caller-sweep-omits-examples**: "no callers" cleanup breaks workspace typecheck and HTTP/HMR tests → fixed packages/apps/tools/services sweep omitted `examples/vite-like-dev` → enumerate `pnpm-workspace.yaml` roots before retiring an API; private examples can carry a tested baseline.

- **new-toplevel-dir-invisible**: a new top-level dir (e.g. `services/`) is silently ignored → workspace/arch/test/backlog tooling hardcodes `packages|apps|tools` → wire 6 spots: pnpm-workspace glob, vitest unit include, `check:arch` args, arch-boundaries sweep, arch-rules carve-out, backlog SCAN_ROOTS; not in `build:libs`; publish build = hand-written tsup config.
- **lockfile-mirror-host**: a committed lock (fixture, backlog `reference/` probe, corpus seed, snapshot, probe output with a lock object) replays only inside one network → `npm install` behind a mirror `.npmrc` writes the mirror into `resolved` (PR #266, #430, #443) → `check:lockfile-registry` refuses it; rewrite the host to `https://registry.npmjs.org`, keep `integrity`, verify `npm ci --cache <empty> --registry=https://registry.npmjs.org/`. It reads index paths but working-tree bytes: `git add` a new lock before trusting a local green; a foreign host staged and then cleaned only in the working tree → local green, CI red (re-stage); an exempt file deleted only in the working tree → local red, CI green (restore or commit the deletion with its row). Not read (declared limits): YAML beyond keyed lines/flow entries, bun/deno locks, `.npmrc`/`.yarnrc.yml`, `.jsonl`, `.zip`/`.tar`, `.tgz`, double-encoded locks, symlinked locks, streaming of huge documents.

- **generated-sw-source-ratchet**: `apps/playground/public/sw.js` is the ADR-0016 bundle, not handwritten source. `check:file-size` excludes exactly that output (replaces its old879-line pin); TS inputs and `build/sw-plugin.ts` stay measured.
