# ADR 0188: Install-time shadow internals shims with companion pins and substitution provenance

Status: Accepted
Date: 2026-07

> Correction 2026-07-13 (ADR-0226): the bridge-backed dual-entry esbuild facade is replaced by one install-time CJS overlay that reads the exact Worker-owned runtime slot. Rollup companions, install-time application, version gates, alias placement, and substitution provenance remain unchanged.

> TL;DR: shadow-registry internals shims move from playground boot-overlay to the npm-client install path — `install()` writes them into the ACTUAL installed package dir (nested/hoisted-aware), version-range-gated with a loud `NotImplementedError` outside the proven range; `rollup` gets a same-version companion pin (`@rollup/wasm-node`) injected into the dep walk so ONE mode-independent `dist/native.js` (real WASM parser) replaces the dev-stub/build split; every shadow substitution prints an `npm:`-prefixed provenance line naming the shadow registry, on fresh install AND lockfile replay.

## Context

Two shadow-registry mechanisms existed. (1) `bakedOverrides` package redirects (`esbuild→@esbuild/wasi-preview1` etc.), applied by the installer silently — the user installs `esbuild` and gets a different package with zero trace. (2) Internals shim file-sets (rollup `dist/native.js`, the `esbuild`/`lightningcss` import-name alias packages), written by playground `overlayShims()` at vite-preset boot only, at hardcoded `/workspace/node_modules/...` paths re-rooted per call site (three copies: dev-server-boot, vite-cli-prep, build-boot). Net effect: preset vite worked, hand-installed vite in a scratch project didn't; nested layouts missed shims; provenance was invisible. Worse, the rollup shim content was RUN-MODE-dependent (dev stub returning an empty ESTree program vs build's real `@rollup/wasm-node` delegate) — impossible to key install-time, where content must be a function of (name, version) alone. Backlog contract: the `npm-client/install-time-shadow-shims` item (delivered 2026-07-02, removed per delete-on-done).

## Decision

- **Application moves to npm-client** (`src/shadow-shims.ts`); data stays in `@riftydev/shadow-registry` (ADR-0015) as `internalsShims: Record<pkgName, { range, into?, files, companions? }>` keyed by the INSTALLED trigger package, files keyed by package-relative path. `install()` applies them after `link()` into each pinned copy's `installPath` (nested copies included). Playground carries zero shim glue; `overlayShims`/`reRootShimPath`/`glue/esbuild-shim.ts` deleted. Vite's `cli.js` keepalive/preview patches stay in `vite-cli-prep.ts` — they are runtime lifecycle/preview-config patches on vite's CLI, not shadow-registry package substitutions.
- **Mode split resolved by companion pins, not per-mode content.** The dev stub is deleted; the single `rollup/dist/native.js` shim always delegates to `@rollup/wasm-node/dist/native.js` (the content the REAL `npm run dev`/`build` CLI path already ran). To make that resolvable in every project, `internalsShims.rollup.companions = ['@rollup/wasm-node']`: the dep walk injects a companion visit pinned to EXACTLY the trigger's version (AST buffer layout is version-coupled; lockstep is mandatory — the bake-time `assertRollupWasmNodeLockstep` guard stays as a net). Companion edges are NOT persisted in lockfile entries: replay re-derives them from (name, version), so the lockfile format is unchanged. The vite template drops its hand-pinned `@rollup/wasm-node` (companion supplies it). The unified esbuild shim ships the real bridge-backed `transform`/`build(write:false)` behind BOTH entries (`lib/main.js` ESM + `lib/main.cjs` CJS — `require('esbuild')` is real Node behavior; a require condition into a `type:module` `.js` would loud-fail the rifty loader's sync require). Everything the bridge cannot do for real is loud, never tolerated: `build` refuses local-file imports in the entry (`esbuild.build.bundle` — single-module transform, no traversal), `context()` constructs only EMPTY (its empty `rebuild()` IS real esbuild's zero-entry result; entry points refuse at construction), non-empty `analyzeMetafile` refuses.
- **Alias packages** (`into: 'esbuild'`, `into: 'lightningcss'`): the file-set materializes a package under the ORIGINAL import name in the SAME `node_modules` scope as the installed redirect target — the mechanical completion of a name-changing override (rifty installs the target under its own name, unlike npm aliases).
- **Version gate:** installed trigger version outside `range` → `NotImplementedError('shadow-registry.<publicName>@<version>')` — never a stale shim silently applied. A replayed companion at a version ≠ its trigger → loud `EBROKENLOCK`-style error ("delete package-lock.json and re-install").
- **Provenance lines** (`InstallOptions.onSubstitution?: (line: string) => void`, default `console.warn` — never silent): baked redirects print `npm: <src>@<range> → <target>@<v> (substituted from shadow registry, ADR-0051)`; shim application prints `npm: <publicName>@<v> internals patched from shadow registry`. Printed on live resolve AND lockfile replay (top-level replay redirects reported from `chooseSource`'s pins; transitive from the lockfile source). User `overrides` do NOT print the shadow-registry line (`resolveOverride` now returns `source: 'user' | 'baked'`) — the user authored those. The playground `npm` command routes the sink to `ctx.stdout`.

## Consequences

- `npm i vite && npm run dev` in an empty project gets the same node_modules shim state as the preset; eddy and the baked-snapshot pipeline inherit everything (both run this same `install()`), so snapshots now bake the shims in.
- Pre-0188 lockfiles for rollup-bearing trees lack the companion entry → explicit `npm install` replay throws `EBROKENLOCK` with the delete-and-reinstall hint (stamped trees keep booting; a fresh install self-heals). A pre-0188 eddy deployment declines/breaks the same way — deploy eddy with the matching npm-client.
- Dev now parses with the real WASM parser in ALL paths (previously only the CLI path did); the empty-program stub approximation is gone.
- Follow-up: the `playground/vite8-prune-dead-shim-overlays` item is subsumed (removed) — vite8 trees no longer receive dead esbuild/rollup shim files at boot.
