# ADR 0302: Vite config cache has bounded generation capacity and no fallback

Status: Accepted
Date: 2026-07

> TL;DR: OwnerVfsAuthority owns an authenticated per-child Vite generated-module
> cache; exact prepared Vite keeps its upstream paths and load order, each run
> holds at most 8 MiB, and every unsupported/failure path throws without writing
> back into the attested dependency tree

## Context

Vite 7.3.6 and 8.0.16 bundle ESM config into a timestamped module under
`node_modules/.vite-temp`, import it, then unlink it. Treating those ordinary
guest writes as harmless would violate ADR-0261. Correct revocation, however,
makes an untouched Vite project dirty, destroys offline reuse, and blocks the
next child admission after initial dev boot.

Redirecting generated bytes requires a finite owner and transport contract.
Chunking below SyncRPC's frame limit does not bound retained memory; silently
falling back to `node_modules` on cache failure would publish false trust.

## Decision

- `OwnerVfsAuthority` is the sole state owner. Its composition exposes only an
  admission capability: exact prepared Vite source is captured while the
  package FIFO reservation is held, then one unforgeable MessagePort delivers a
  per-child token. Silent admission is bounded to 10 seconds; timeout closes the
  peer and throws before sync RPC. A project/session/child fence retires that
  generation.
- Acquisition patches exactly one Vite bundled-config site before install-claim
  promotion. The patch redirects only mkdir/write/unlink backing. Vite still
  chooses `nodeModulesDir`, timestamp/random basename, `pathToFileURL`, bundle,
  import, and finally ordering. Anchor absence/duplication throws
  `NotImplementedError('playground.vite-config-temp-cache')`.
- The child loader overlays only generated files owned by its generation and
  injects the client into the exact path-and-byte-attested Vite module under
  ADR-0301. Ordinary `node:fs`, page, terminal, archive, Git, and runtime VFS
  access retain the base authority and cannot enumerate or mutate the cache.
- A generation reserves at most `8 * 1024 * 1024` live bytes. Pending and
  committed files count; remove, abort, and retirement release capacity.
  Upload/read chunks are at most `256 * 1024` raw bytes, below the 1 MiB SyncRPC
  frame after encoding.
- Capacity overflow throws
  `NotImplementedError('playground.vite-config-temp-cache.capacity')` before
  allocation. Transport, storage, anchor, and cleanup failures keep their
  provenance. None may fall back into the project tree or report Vite ready.

Rejected: `.vite-temp` path whitelist; post-mutation re-promotion; hidden
`npm install`; runner/native config loaders; owner-external cache state;
generation-derived filenames; unbounded allocation; fallback writes.

## Consequences

- Untouched Vite config evaluation no longer changes project bytes, install
  readiness, Scratch dirty state, or offline-reuse eligibility.
- Node-valid bundled config above 8 MiB is an explicit compatibility ceiling
  until a successor decision changes the bound or storage mechanism.
- Exact upstream anchor, Vite version, and install-artifact identity move
  together; unsupported bundle drift fails acquisition rather than weakening
  trust.

Cites ADR-0084 (SyncRPC capacity), ADR-0261 (install trust), ADR-0300 (entry
capabilities), and ADR-0301 (exact lexical binding).
