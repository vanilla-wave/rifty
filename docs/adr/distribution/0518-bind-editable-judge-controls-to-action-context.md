# ADR 0518: Bind editable judge controls to action context

Status: Accepted
Date: 2026-10

## Context

Extends ADR0512/0516/0517, overturns none. Public workflows permit creation and
inline editing together. Captured v7 noCOI1 Room name getter selects2. Real Vue
reference40GREEN; independent creation/editor layout through SAME validation/
commit owner public workflow GREEN/private strict RED. Svelte twin similarly:
originalPASS/dual description strict RED. Scalar global-purpose assumption fails.

## Decision

One action-context control projection. Preserve existing singleton lookup;
otherwise use native form ownership (including external form-associated fields),
then the closest containing context with one matching control around
its intended named action; unresolved purpose/action remains a loud ambiguity.
Creation prefers add/create, editing prefers save/update, shared editor falls
back to its available action. No field order, exclusive editor, DOM tag/class
or new state owner. Native fields keep existing representability and purpose.
Checkbox/toggle selections use the same owner; no per-case first-field shortcut.

Global unique purpose rejected by actual two-programme RED. Globally first
control ignores creation/edit intent and order; native target-state guards
reject it. Requiring hidden creation while editing would strengthen open-layout
public contracts; rejected by I6. No second renderer/coordinator or UI protocol.
