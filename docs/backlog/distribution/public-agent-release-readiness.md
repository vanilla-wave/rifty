## Context

`@riftydev/agent` already owns the Pi loop, public host adapters, Stop/recovery,
limits and trace, and its packed Workbench/no-COI consumer proofs landed in PR
#333. ADR-0424 kept it private and deferred publication. The public npm name is
absent. Pi's native custom stream seam is sufficient, but rifty currently creates
an OpenAI model before selecting it, forcing a callback consumer to invent
`baseUrl` and `model`; export then records those values. Rifty-owned shell and
preview-fetch tools leave decisive outcome metadata only in `details`, which is
not a portable model-facing channel.

## Challenge

challenge: 2026-09-14 — clear

- Value follows: a private package cannot serve ordinary external npm consumers;
  publishing unchanged retains fictitious transport settings and ambiguous quiet
  tool outcomes.
- Consumer wrappers and publish-now/fix-later do not reach a truthful reusable
  agent. The smallest route reuses native `StreamFn`, fixes rifty-owned text and
  trace provenance, and preserves the existing OpenAI/Playground path.
- No provider/model catalogue, domain abstraction or consumer-specific workflow
  belongs in scope. Exact option names, trace shape and text encoding are
  implementation-owned. No material user fork remains.

## User scenario

An external browser application installs `@riftydev/agent` at the rifty lockstep
version, creates a session over a public host, passes a native Pi `StreamFn`,
instructions and domain tools, then sends an edit/build/preview prompt. It supplies
no dummy endpoint/model. Each subsequent callback turn can distinguish quiet
shell success, nonzero exit, failed/error outcome, cancellation with worker/effect
uncertainty and preview HTTP failure from the bounded text it receives. Export
identifies custom transport without invented configuration and retains actual
assistant response metadata. The existing OpenAI-compatible Playground flow
keeps working with its UI-owned proxy help.

## Reference contract

- Oracle: `@earendil-works/pi-agent-core` and `@earendil-works/pi-ai` 0.85.1.
- Mechanism: native `StreamFn(model, Context, SimpleStreamOptions)`; context owns
  current system prompt/messages/tools and request options own `AbortSignal`.

## Acceptance

1. `@riftydev/agent` is generated by the public-package SPEC, has only its root
   public export, packs compiled JS/declarations/docs, and joins the documented
   17-package lockstep release set; the PR performs no registry mutation. → scenario
2. Session options admit exactly the OpenAI-compatible settings transport or a
   native custom `StreamFn`; custom mode needs no endpoint/model/fetch settings,
   receives current Pi context and abort, and may choose its model per call.
   Existing OpenAI settings/fetch behavior remains. → scenario, ADR-0436
3. The following custom callback receives distinct capped standard-tool text for
   quiet shell exit 0, exit nonzero, failed status/error, cancellation and each
   reported worker/effects state, plus preview HTTP success/failure; structured
   details and Pi error semantics remain intact. → scenario, ADR-0436
4. Custom trace config claims only custom transport and shared limits; actual
   provider/model/API/usage metadata comes from retained assistant messages.
   OpenAI trace config retains its real endpoint/model and no API key. → scenario, ADR-0436
5. Generic agent network failures contain no Playground-only advice; the
   Playground still shows its development-proxy guidance for the same failure.
   → scenario, ADR-0436
6. Existing real packed Workbench and no-COI agent consumer proofs pass with the
   public package manifest, alongside package typecheck/build, tarball inspection
   and the full PR gate. → scenario

## Fault matrix

## Out of scope

- Actual npm bootstrap, trusted-publisher mutation, release tag or publish.
- Consumer-specific wire schemas, authentication, UI, domain actions and save
  policy.
- New provider/model catalogue, `setModel`, chat restore, subagent orchestration
  or cross-origin DOM preview.
- New semantics for consumer-owned tool result text; image results retain
  `NotImplementedError('agent.tool-image-result')`.
