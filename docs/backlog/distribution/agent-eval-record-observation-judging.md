## Context

F6: same working programmes, only Edit captions gain `details for`; current
criteria fail. Permanent actual native baseline:10 selected,8 old PASS,2 RED.
Caption/read-only notes, loaded values and sticky Validation cannot establish
savedness. Positive action receipts also overcount aliases; identical expenses
cannot be merged by their payload. Current source remains unchanged.

The repair introduces an explicit observation lifecycle at the existing caller
Edit/read/Save seam. Candidate queries remain pure. Public task inputs/layout/
data representations remain open; prototypes are feasibility, not UI schema.

## Challenge

challenge: 2026-10-09 — inherited accepted goal premise; independent DEC audit killed cheaper pure/load/no-op routes and flat receipt counting. Contract+RED verifies missing preparation before implementation.

## Reference contract

- Authority: unchanged booking/expense public prompts; actual Vue3.5.18/Svelte5.38.7 programmes on Vite7.3.6, Node24.16.0/Chromium148.0.7778.96.
- Oracle: independently executed public operations, saved effects and native fixture rollback checks; never a caption grammar, field-only savedness claim or storage schema required from generated apps.
- Mechanism: domain-unique room/person names and reservation room/date/start keys where public constraints guarantee uniqueness; persisted temporary identity for duplicate-capable expenses. Local observation lifetime; no execution coordinator or persistent registry.
