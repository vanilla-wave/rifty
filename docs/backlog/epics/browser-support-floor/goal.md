## Outcome

`docs/public/compat/browsers.md` exists: per mode (COI, non-COI) × persistence (ephemeral, persistent) × engine column (Chrome, Edge, Firefox, Safari, Chrome Android, Safari iOS, Samsung Internet, Yandex Browser) the minimum version with its binding requirement and an evidence mark from the ADR-0469 legend (`N` computed / `⚙N` probe / `✅N` lane on build + date / `⚠N` lane with recorded reds / `❌` / `❓`), the non-version cut-offs (secure context, CSP, private modes, Lockdown, eviction, memory) and the traffic share (numerator: versions at or above the floor; denominator: all tracked traffic, caniuse-lite usage weights, global and RU; the RU coverage gap — Yandex Browser absent, RU sum ≈ 67 % — and the StatCounter cross-check stated as caveats). Hand-maintained, dated; numbers move with executed evidence or a landed change plus its guard/test; the only widenings are the cheap ones the user accepted (round-2 "1a": the `preferred` memory fallback; round-3 "a": the `toSorted` rewrite, Chrome floor 108, ES2022), the three expensive levers stay questions ("2a"). Around it: an ES-floor guard so the computed floor cannot drift with the next builtin; loud capability errors where the runtime today fails late or hangs; cross-engine lanes (Firefox, WebKit) and a floor-smoke lane on the floor builds, run by manual dispatch — no schedule, no release gate — feeding dated rows; a one-URL manual protocol for Safari / iOS / Yandex rows; native macOS Safari and Yandex are measured, while physical iOS execution is excluded by the user amendment and its row remains explicitly unmeasured. Faithful-runtime payoff: a browser gap is a named loud throw at boot, never an `EIO` milliseconds into the first write or a hung open.

## User scenario

1. A host engineer opens `docs/public/compat/browsers.md`. Non-COI persistent row: Chrome `✅108`, Firefox `✅114`, WebKit `✅26.0` (engine build) plus the real-Safari manual row, each with binding API, build and date; non-COI ephemeral row: Safari `16.4` once the gate landed (`❌` with the P1 reason before); COI row: Firefox `145`, Safari `❌` (D-001). Reads the traffic share, its method and its RU caveat, and answers the host's question with the legend in hand.
2. The same host ships to a Safari 18 user. With the default `persistence: 'preferred'` the sandbox runs memory-backed and exposes the reason (`createWritable` missing); with `'required'` `createSandbox` rejects at boot with a capability error naming `FileSystemFileHandle.createWritable`; `checkSandboxSupport({ persistence: 'required' })` reports the same unmet check. No path selects OPFS and loses data on reopen. On a realm whose OPFS root is unavailable, `'required'` rejects naming the storage failure with its native error; `'preferred'` falls back to memory and says so.
3. A contributor adds `Object.groupBy` (ES2024) or `toSorted` (ES2023) to a shipped worker: `pnpm pr:check` fails naming the file and the builtin.
4. On manual dispatch the cross-engine lanes run on Firefox and WebKit; the dated per-engine result of that named run lands in browsers.md; a product red becomes a recorded finding with its class, never a silent skip and never a PR block. No schedule, no release gate.
5. On demand (a floor change or a Playwright bump, never scheduled) the floor-smoke lane executes boot → install → build → reload → reopen on Chrome 108 / Firefox 114 / WebKit 26.0 builds; ✅ or ❌ + failing step lands in the table.
6. One URL supplies the protocol for Safari, iOS Safari and Yandex Browser. Native Safari 26 (macOS) and Yandex results are recorded with storage estimate and per-step outcomes, memory and eviction where observable, else ❓ with the reason. Physical iOS execution is excluded; its row stays ❓ with no product observation or hardware-support claim. A simulator result, if available, is separate and optional.

- I2. - I3.
