## Context

ADR-0143 chose **D (owner-worker)** over B (SAB fs-proxy). D is milestone-scale (blast radius kernel + shell + terminal + playground + net) with several IRREVERSIBLE sub-decisions → its own ADRs. Subsystem map (verified 2026-06-14): kernel process model is mature (`WorkerProcessHandle` already has stdin/stdout/stderr streams + kill + IPC); the real-vite preview worker is the working "owner" prototype (owns its install, serves the page over snapshot/nm-read/write ports, stays alive). Most of D = generalize that owner into the shell's home + give the kernel a real persistent-process lifecycle.

### Decided forks (recorded; do not re-litigate)

- **One owner per workspace** hosts BOTH the shell and the preview (ADR-0143 destination; separate owners = the two-owners trap). The dev server is **co-resident** in the owner realm for v1; true concurrency ("shell responsive while `vite` runs") needs P6 (SAB sync-views, worker→worker).
- **P2 pty channel** = the existing structured line/chunk/signal/stdin/exit protocol (matches the current terminal contract), NOT a raw-byte pty.
- **Whole Shell moves** into the owner-worker (`packages/shell` is realm-agnostic — io+vfs only); the PAGE terminal keeps local line-editing (it already fires one line per Enter) and becomes a thin client; cwd/env/execution live in the owner.

## Phases (ordering: P1 gate → P2 + P3 → P4 → P5 → P6)

- **P1 — kernel server-process model. ✅ LANDED (ADR-0144).** `serve` flag on `WorkerSpawnSpec`/`SpawnWorkerSpec`; the kernel no longer reaps a `serve` worker when its entry settles cleanly (`finalizeWorkerEntry`). real-vite migrated off the `await new Promise<never>(()=>{})` keep-alive hack. Unit-tested (`worker-entry-serve.test.ts`); real-vite COI e2e re-verify pending a COI run.
- **P2 — PAGE terminal → thin client over a pty channel. ✅ LANDED (ADR-0146, corrected 2026-06-23).** `Shell` + cwd/env + npm-install moved into one persistent workspace-owner (`real-vite-bootstrap` mode-parametrized `shell`|`preview`, spawned `serve:true` at App-mount, addressed by `workspaceId`). pty channel = `pty:*` frames on the kernel fork-IPC port (control + stdout/stderr chunks on ONE ordered channel → no chunk-vs-exit race; `sessionId`+`runId`; cwd/env pushed on `pty:exit`; structured `pty:ready` replaces the stdout log-match + retry-storm). New `pty-protocol`/`pty-server`/`pty-client`/owner execution seams; `terminal-manager.ts` → pty port client; dead `shell-adapter`/`useShellSession` removed. **Correction:** the final `.bin` path did not keep every CLI in the owner realm: P6a moved bins to supervised child Node workers that read the populated owner store over remote sync fs, closing ENOENT for real package-tooling CLIs while keeping the owner responsive. `execSync` node-entry shebang/relative-import routing remains a separate residual (`docs/backlog/runtime-js/execsync-node-entry-loader.md`). Persisted cwd/env restored via `pty:open` seed; `npm run <dev>` routed page-side (pre-P2 parity). No kernel/`shell`/`terminal` source change. Unit-tested (`pty-*`, owner session, thin client); COI e2e `owner-shell-cowsay.spec.ts` (CI-only). **Tracked transient → P4:** the dev-server preview owner stays separate (page-driven `dispatchDevServerLine`) so the preview does NOT yet see terminal-installed deps; **P4** folds the vite tail co-resident into THIS persistent owner (subsumption, not rewrite) — zero residual debt at D close. **Post-merge fixes (CI e2e, COI-only, missed at local green):** (1) fork-IPC message-drop race — `WorkerNodeProcessShim` dropped `ipc:message` frames emitted before the slow owner bootstrap registered `process.on('message')`, so `pty:open` was lost and EVERY shell command hung (no output); fixed by buffering+flush-on-first-listener in `runtime-js/ipc/install-process.ts` (`install-process-ipc.test.ts`). (2) preset `files[]` reached only the preview worker → owner shell ENOENT; `seedViteWorkspace` now pushes them to the owner via new `WorkspaceOwnerHandle.writeFile`. (3) PAGE-driven dev tab `data-running=false` → tabs reflect `devServerRunning` for the owning session. (4) cowsay e2e raced the install (matched mid-stream `+ cowsay@`, typed into busy shell) → waits for the install-complete summary. e2e-chromium green.
- **P3 — generalize the owner-served ports** (snapshot / nm-read / vfs-write) so the PAGE editor/explorer read+write the owner store the same way the thin terminal does. Reuses shipped machinery; widen node_modules-scope → general read; add write-coherence (owner = source of truth). Sibling of P2. **✅ LANDED (Option A, scoped minimal — REVERSIBLE, CHANGELOG, no ADR).** (1) Owner republishes its snapshot on every `pty:exit` → page explorer reflects shell-written files (`echo > f`, program output) without a dev-server restart (e2e `owner-explorer-coherence.spec.ts`). (2) Structured readiness handshake (`snapshot-req`/`serveSnapshotRequests` + page `requestVfsSnapshot` on subscribe) replaces the owner's blind `[300,1200,3000]ms` retry-storm — deterministic initial sync + reload (unit `vfs-snapshot-port.test.ts`). Editor writes already reach the owner (`WorkspaceOwnerHandle.writeFile`, P2 fix). **Deferred to P4:** general (non-node_modules) on-demand read-port widening — a server capability with no consumer until the editor opens large/owner-only files; folds in when the preview owner unifies (no silent stub). Full owner-as-single-source-of-truth (retire page-vfs + triple-write) also lands at P4 (Option B was declined for P3).
- **P4 — unify with the real-vite preview owner. ✅ LANDED (ADR-0148).** `vite`/dev runs CO-RESIDENT in the SAME owner that holds node_modules + the shell — started on demand by the owner's `vite` / `npm run <script>` command, stopped on Ctrl-C via `server.close()` without killing the owner — so the dev server reads just-installed deps directly (closes the two-owners trap; COI e2e `m7-preview-sw` co-resident vite, `fullstack-demo` node-server, `owner-shell-cowsay` shell). The per-run `startRealVite` preview worker + the page-driven dev path (`dispatchDevServerLine`/`runViteCommand`/`isDevServerLine`) are DELETED; dev-server status+port flow over a structured `pty:dev-server` frame + the P3 request handshake (no stdout log-match); `wirePreviewBridge` does the page-side preview SW wiring. **Forks resolved:** ONE big ADR (vite-unify + SSoT together, user pick); start mechanism = reuse `pty:exec` (user pick); co-resident v1 (prior ADR). **SSoT for the read + exec path landed:** editor + explorer ALWAYS read the owner snapshot (`activeVfs`/`snapshotFs` swap retired), editor + program writes go to the owner (HMR against the served store), and the `node_modules` read-port is widened to a general workspace read-port whose consumer is the editor opening owner-only files (via the async read-port fallback). New `dev-server-controller` (single-active guard + HMR forward) + `pty:dev-config` (preset switch re-resolves the owner's runtime so a node-server preset boots its own runtime/port). **Residual debt:** the page kept a SECOND authoritative `syncMirror` (`initBackend`) written-through as a workspace-archive copy → D-acceptance A1/A2 `partial`; retired below.
- **A1/A2 — retire the page authoritative VFS. ✅ LANDED (D-acceptance, post-P6a; REVERSIBLE, CHANGELOG, no ADR).** Removed the page-side store P4 left behind: archive export/import is owner-served (`glue/workspace-archive-port` — req/resp over the snapshot port, reusing the realm-agnostic `glue/workspace-archive` against the owner `syncMirror`, full content no 128 KB cap), so the downloaded archive is faithful to shell/CLI-authored files; seeding + the default README are owner-only (`real-vite-bootstrap` `seedProject`); terminal cwd validation moved to the owner (`glue/reachable-cwd` in `makeShell`, TDD); the storage badge reads `detectVfsBackend` (no page install — also fixes the old page-main-thread "OPFS-sync-fails → badge shows memory" lie). The page now constructs NO store → authoritative-store count == 1; A1/A2 hold. e2e `owner-*` + `sandbox-fs-rpc` green; unit `workspace-archive-port`/`reachable-cwd` TDD.
- **P5 — OPFS persistence in the one owner. ✅ LANDED (CHANGELOG, REVERSIBLE — no ADR).** The owner now `await initBackend()` at boot (it was the ONLY worker realm not doing so — `runtime-js/worker-entry`, `rifty/sandbox` already did), so `syncMirror()` is OPFS-backed and the OPFS content-cache write-through (ADR-0072, `O(total bytes)` preload accepted) persists the tree across `page.reload()` (e2e `owner-persistence-reload`). **Durability = the write-through itself; NO per-command flush barrier** — an awaited `pty:exit` flush drains the WHOLE pending queue, so during boot every command's exit blocked on the unrelated node_modules-restore I/O, stalling the shell + flaking e2e (reverted). **Two regressions enabling OPFS exposed, fixed with tests:** (1) `runtime-js` temporarily preferred the sync content cache because `OpfsVfs.openReadable`'s `File.stream()` stalled under cross-realm preview serving; this was later closed by restoring async-first `createReadStream` over chunked `openReadable`; (2) `terminal-persistence` serializes its fire-and-forget OPFS history/state saves (owner OPFS I/O could reorder them, dropping the latest command). **Deferred:** graceful drain-on-terminate (hard-kill still loses the last in-flight write — backlog `shell/owner-graceful-drain-on-terminate`); node-server graceful dev-server stop → P6 (needs re-listen-on-restart = fresh per-run realm; closing http without it regresses today's restart).
- **P6 — SAB sync-views for concurrent spawned processes** (worker→worker, B's mechanism served the right direction) — restores "shell usable while a CLI/dev-server runs" by giving each foreground process its own realm sharing the owned store. Needed because the single owner realm is one JS thread. Own ADR **0150** (scope A: every foreground process → supervised child; owner = pure async supervisor + fs-server; binding `waitAsync` invariant = no blocking work on the owner thread). Sequenced:
  - **P6a — CLI/bin → supervised child. ✅ LANDED (ADR-0150).** The frozen `BinExecutor` seam (ADR-0137) swaps from in-realm `createOwnerBinExecutor` to `createOwnerChildBinExecutor` (spawns a node-entry child via `globalProcessManager.spawnWorker`, `RIFTY_REMOTE_FS=1`, reusing `glue/bin-executor.ts`'s stream/kill); bin RESOLUTION stays owner-side. New `fs.*` sync-RPC surface (`runtime-js/ipc/fs-handlers.ts` owner-serves `getKernelDispatcher()`; `SyncRpcFsSync` child-reads; chunked read/write under the 1 MiB ring; `installRemoteSyncFs` swaps the child's GLOBAL mirror so `node:fs` + loader both route to the owner). Owner gets kernel/node-entry worker URLs via env (recursive spawn, COI-proven). **3 latent gaps the child path surfaced + fixed:** child `process` missing Node identity fields (`versions`/… → shared `NODE_PROCESS_IDENTITY`); child `node:fs` read the empty realm mirror not the owner (→ `installRemoteSyncFs` global swap); child `console.log` not wired to its stdout port (→ `installConsole` in the bootstrap). e2e `owner-shell-cowsay` (child reads node_modules over RPC, draws), `owner-shell-responsive` (two concurrent children + Ctrl-C kill). Recursive-spawn-from-owner + remote VFS validated end-to-end.
  - **P6b — dev server → supervised child. ✅ LANDED (ADR-0150).** The `dev-server-controller` injected `boot` (`dev-server-controller.ts:37`, state machine UNCHANGED) now spawns a `serve:true` child (`createOwnerChildDevServer` → `dev-server-child-bootstrap`) instead of running `bootDevServer` in-realm; `bootDevServer` + its vite/node tails were extracted verbatim to `dev-server-boot.ts` (importable by the child). The child reads+writes the owner store over the P6a `fs.*` sync-RPC ring (`RIFTY_REMOTE_FS=1`). Only `serveCrossRealmPreview` relocates to the child — `setupPreviewBridge` is page-side/inert-in-worker (ADR-0150 corrected). Owner↔child fork-IPC: `rifty:dev-ready`/`-error`/`-snapshot` (child→owner), `rifty:dev-file-changed` (owner→child HMR); new `RIFTY_DEV_SERVER_WORKER_URL` env (page→owner). node-server graceful stop folds in: `stop()` kills the child, a fresh child per run re-binds the port (re-listen-on-restart). **Gates green:** unit (`dev-server-ipc`/`owner-child-dev-server`/`dev-server-child-config`), gold e2e (`m1-terminal-shell`/`m7-preview-sw`/`fullstack-demo` preset-switch), prod smoke (`owner-boots-on-prod-build` — the new child URL survives the prod bundle). **Bug found+fixed by the gold e2e:** the node-server entry bound the owner's spawn-default `PORT` (5174) not the preset's dev port (3210) → `buildDevServerChildSpawnSpec` now sets `PORT`=devPort in the child spawn env (the clobber-safe source the entry reads). **Honest acceptance gap (B5):** owner-non-blocking is now a STRUCTURAL guarantee (the dev server is a separate worker — it cannot run on the owner thread), but a shell-latency RED→GREEN under load is NOT demonstrable for current workloads — empirically (489 probes, ~zero margin) the co-resident install/transform pipeline already yields (`npm-client await`, `DecompressionStream` gunzip, async sql.js), so the owner never synchronously starved; recorded honestly in `process-meta/test-coverage-debt` (same class as the existing owner-shell-responsive note). **P6 complete → all D phases P1–P6 landed** (D-acceptance sign-off + the honest B5 caveat aside).

## Open design forks (resolve at the owning phase)

- P2: per-session isolation — N in-realm Shells in one owner (shared thread) vs one worker-process per session (needs P6). v1 = shared; isolation at P6.
- P2: cwd/prompt ownership — owner is source of truth, pushes cwd snapshots to PAGE for the prompt + persistence.
- P4: is the dev server a co-resident task or a child worker-process the owner supervises? v1 co-resident; supervisor at P6.
