## User scenario

Run `pnpm bench:child-fs -- --runs 1 --out perf/child-fs-baseline.json`
from a clean checkout. One strict-port Vite server and one Chromium page execute
both real lane fixtures for each ordinal. The command emits no success file
until the exact sample set passes the shared artifact authority; the committed
baseline records raw before-optimization evidence for I1/I2.

## Acceptance

- The package script accepts only the existing strict CLI form
  `--runs N --out <path> [--port P]`. It parses and admits a free localhost port
  before spawning anything, then starts exactly one playground Vite process and
  one Chromium instance against `/unit-harness.html` with real COI.
- A browser orchestration fixture runs product-coi then in-realm for ordinal
  `1..N`, using their real hosts and returning only raw samples. The Node runner
  independently verifies exact N×2 lane/ordinal identities through
  `buildChildFsArtifact`; browser/lane code cannot report digests, environment,
  git SHA, summaries or a partial aggregate.
- Server readiness, each page sample and process shutdown have fixed generous
  deadlines. Dev-server early exit, page crash/close, lane rejection, timeout,
  malformed sample or incomplete N rejects the command; page/browser/server are
  closed once and `publishChildFsArtifact` is never called.
- Success records exact git SHA, generated-at ISO string, Chromium version,
  canonical digests, owner-load `idle`, raw Vite/Express proof and derived facts;
  it publishes pretty JSON plus newline through the shared sibling-temp atomic
  writer only after browser and server cleanup succeed.
- `perf/child-fs-baseline.json` is generated by that command on the landed rig,
  validates byte-for-byte through `validateChildFsArtifact`, contains one
  complete sample per lane, and has its two self-times recorded in the goal
  ledger. No multiplier/pass threshold is stored.

## Parity cases

- `two-real-lanes`: one browser page records product owner→kernel-child and one
  single-Worker sample for the same canonical ordinal; both report 2180 modules
  and matching raw-proof invariants.
- `artifact-identity`: CLI-owned environment/git/generatedAt plus exact two-lane
  samples round-trip through build, JSON serialization and validation without
  projection or rounding.
- `all-or-nothing`: every launch/lifecycle/sample/storage failure exits non-zero
  with no new success artifact or surviving process.

## Fault matrix

| Boundary / axis | Required outcome | RED target |
|---|---|---|
| dev server/page `provenance-lie` / failure | early exit/crash/close rejects; cleanup once; no publish | fault-labelled injected lifecycle actions |
| registry/lane `unbounded-read` / failure | fixed sample deadline rejects hung/failed lane and closes page/browser/server | never-settling/rejected sample action |
| sample set `corrupt-input` / `lossy-aggregate` | wrong/duplicate/missing lane ordinal cannot reach artifact/publication | real browser result + shared builder mutation table |
| artifact storage `quota-perm-fail` / `torn-state` | shared atomic publisher failure is loud after cleanup; no partial success | injected publication action + inherited writer faults |

## Out of scope

- Performance thresholds, computed speedup/multiplier, CI gating, loaded-owner
  mode, parallel samples, retries, or a reusable browser pool.
- Hot-path implementation changes; this is the frozen I3 measurement boundary.
- A second port guard, artifact writer, schema, scenario or lane implementation.
