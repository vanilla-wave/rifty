# Compatibility matrix — installed Vite command

Generated by `pnpm compat:generate` from static inventories backed by conformance and parity tests.

Public claim surface for exact Vite 7.3.6 and exact Vite 8.0.16 through the installed `node_modules/.bin/vite` CLI (ADR-0174/0226/0243/0308/0317); rows that run Vite are exact-version ceilings (⚠️). Vite 7 needs the exact esbuild 0.28.0 twin: `npm install` refuses an esbuild range that does not admit it (`esbuild.version`, Vite ≤ 7.3.5), and 7.3.7 installs but its actions stop with `vite esbuild runtime supports exact Vite 7.3.6; executed 7.3.7` (`--help`/`--version` still run). Vite 8.0.16 needs the `@napi-rs/wasm-runtime@1.1.6` override that the Vite project definition adds (a hand-written manifest must declare it); other 8.x run unclaimed, and ≥ 8.2 fails `npm install` on `lightningcss ^1.33.0`.

Legend: ✅ implemented and tested · ⚠️ partial / known caveat / exact-version ceiling · ❌ not implemented (throws `NotImplementedError` or `UNSUPPORTED_PROTOCOL`).

| Feature | Status | Notes |
|---|---|---|

## Known Limitations

- Exact esbuild-backed claim is Vite 7.3.6 with esbuild 0.28.0; exact Vite 8.0.16 dev/build/preview uses Rolldown with an empty esbuild plan and keeps HMR disabled in visible template config.
- Vite 8 `vite optimize`, other Vite 8 versions, and broader config/plugin parity are not claimed by the Vite 8 build/preview smoke.
- Preview traffic traverses the same-origin Service Worker/owner bridge, so `preview.cors` and `preview.allowedHosts` need direct-Node differential proof.
- Fallback-port publication when the requested Vite port is busy still needs browser proof; no hidden `strictPort` force exists.
