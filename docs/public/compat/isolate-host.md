# Isolate host (`@riftydev/isolate-host`, ADR-0557, ADR-0563, ADR-0568)

`runCode(code)` runs `code` like `node -e <code>` on Node 24. Tests:
`packages/isolate-host/tests/` (vitest project `isolate-host`). The oracle is a live `node -e`
child.

| Surface | Status | Notes |
|---|---|---|
| `{stdout, stderr, exitCode}` of CommonJS `node -e` code | ✅ | Corpus parity `parity.test.ts`: console, byte `process.stdout.write`, UTF-8, `exit`/`exitCode`/`'exit'`, event-loop order, an interval's period, a slow interval and 20000 intervals keeping pace (an interval keeps Node's period from its tick's start and never queues behind its running callback, ADR-0558 Decisions 2026-11-19), fs on the in-memory VFS, Buffer, path/util/crypto hashes/events, uncaught throw/rejection diagnostics (canonical `[eval]` projection) |
| Fresh isolate per call, sequential or concurrent, inside shared warm workers (4 calls per worker) | ✅ | Files, globals, timers, unsettled promises and output stay with their call. `isolation.test.ts`, `pool.test.ts` |
| Limits: time / isolate heap / V8 fatal OOM / worker RSS / output cap | ✅ | `termination: 'timeout' \| 'memory'` for the guilty call. The worker RSS ceiling (256 MiB + 3 × the sum of its calls' `memoryLimitMb`) is a sampled watchdog that can overshoot by one allocation step; crossing it with no isolate to blame is a lost worker (row below), not `memory`. Output past the cap is dropped (`truncated`). `limits.test.ts`, `pool-faults.test.ts` |
| A culprit next to other calls on one worker (heap limit, fatal OOM, busy loop, `Atomics.wait`, a builtin ignoring termination, output or interval flood) | ✅ | The culprit gets `memory`/`timeout`; each neighbour gets its solo result, once. A guest still running 1 s after termination retires its worker, and its neighbours finish there. `pool-faults.test.ts` |
| A deadline shorter than the delay a culprit or a rerun costs a call (a neighbour, or a culprit whose memory grows slowly outside its heap and is lost late) | ⚠️ | `timeout` (never a rerun) or, after a lost worker, `ERR_ISOLATE_HOST_WORKER_LOST`: the deadline counts from the call, across a rerun (ADR-0563 §6). Observed: how late a slowly growing culprit loses its worker grows almost linearly with host load — the interval-churn loop at 64 MiB with three 64 MiB neighbours (1024 MiB ceiling), macOS arm64, 12 CPUs: 9 s at load average 33, 40–43 s with 48 `yes` processes (load 120–140), then 12–13 s for its solo; a 60 s deadline ended LOST 1 in 10 suite runs there |
| A worker lost with no culprit known (external kill, OOM-killer, crash, RSS ceiling without a signal) | ⚠️ | Not in Node. Each call reruns once, alone, on a worker of its own, inside its deadline; there an exhaustion of the process is that call's `memory` (wasm, resizable buffers, ICU, timers: `pool-faults.test.ts`). Its own worker lost again, or a rerun past the deadline, rejects with `code: 'ERR_ISOLATE_HOST_WORKER_LOST'` (no guest text). `pool-faults.test.ts` |
| A consumer whose event loop is starved past a call's deadline (a loaded host) | ⚠️ | The deadline is judged by what the consumer reads first, not by when the worker sent it: a result that arrived before the deadline can be returned as `timeout`, and a worker lost before it as `timeout` with no rerun. `protocol.test.ts` (starved-consumer cases), `backlog/distribution/isolate-host-starved-deadline-outcome` |
| A culprit that exhausts its worker only on its first attempt, or only late (adaptive) | ⚠️ | The solo rerun names deterministic exhaustion only: such a culprit can escape blame (its rerun may end `exit 0`); the neighbours pay the rerun and may end `ERR_ISOLATE_HOST_WORKER_LOST` with little budget left (ADR-0563 §7) |
| `code` longer than `memoryLimitMb` / 8 MiB | ⚠️ | Refused: `EvalError: Code generation from strings disallowed for this context`, exit 1 (cause unverified) (Node: runs, up to the OS argument limit). `backlog/distribution/isolate-host-code-longer-than-memory-limit-eighth-evalerror` |
| Platforms | ⚠️ | Tested on darwin-arm64 and linux-x64 (CI); Windows (an isolated-vm prebuild exists) is not tested |
| `SharedArrayBuffer` with `allowSharedArrayBuffer: false` | ❌ | The global is absent for feature detection. Direct construction by name throws ReferenceError. Wasm operations returning shared buffers throw `NotImplementedError('isolate-host.SharedArrayBuffer')`. Native Atomics on ordinary typed arrays: wait/waitAsync throw TypeError, notify returns zero, store/load work. Default and explicit true retain Node behavior. `shared-array-buffer.test.ts`, `embedder.test.ts` |
| Side channels between isolates of one worker (including `performance.now` at ~3 µs) | ⚠️ | Declared open class, not mitigated: tenants that must not share a process need separate consumer processes (`docs/public/trust-model.md` §Isolate host) |
| Network: `fetch`, `WebSocket`, `node:http`/`https`/`net` | ❌ | `NotImplementedError('isolate-host.<api>')`; `node:tls`/`dgram`/`http2` keep rifty's loud stubs. `egress.test.ts` |
| `URL`, `URLSearchParams`, `structuredClone`, web streams, `AbortController`/`AbortSignal`, `Event`/`EventTarget`/`CustomEvent`, `Blob`/`File`, `Request`/`Response`/`Headers`/`FormData`, `MessageChannel`/`MessagePort`/`BroadcastChannel`, web-stream reader/controller/strategy classes, `CloseEvent`/`MessageEvent`, `URLPattern`, `Crypto`/`CryptoKey`/`SubtleCrypto`, `Navigator` and `navigator.*`, `Performance*` classes, `crypto.subtle`, `performance.mark`/`measure`/`nodeTiming`/… | ❌ | `NotImplementedError('isolate-host.<api>')`; successor goal (`docs/ROADMAP.md` M14 B) |
| Static members of those ceiling globals (`AbortSignal.timeout`, `URL.canParse`, `Response.json`, …) | ❌ | `TypeError: … is not a function` — not the named gap; constructing or calling the global itself is |
| `node:zlib`, `node:child_process`, `node:worker_threads` | ❌ | `NotImplementedError('isolate-host.<module>')` at require (rifty builds them on CompressionStream / Workers) |
| Unhandled rejection with a reason isolated-vm cannot copy (function-bearing or null-prototype object, symbol) | ⚠️ | The run fails (exit 1) as in Node; the reason is replaced by `Error: isolate-host: an unhandled rejection reason that cannot be copied out of the isolate` |
| ESM syntax in `-e` (static `import`, top-level `await`) | ❌ | Node 24 detects and runs it as a module; here `NotImplementedError('isolate-host.node-eval-esm')`. `backlog/runtime-js/node-cli-esm-eval-context` |
| `import()` | ❌ | Any form (top level, `await` in an async function, `eval`, `new Function`, a timer) ends the run: stderr gets `Error: Not implemented: isolate-host.dynamic-import (… use require(), ADR-0557)`, exit 1, output produced before it kept. A `.catch` cannot keep the run alive — the gap is reported where the host sees it, since a guest may never observe the rejection. With the output cap already full the gap text is discarded like any output, leaving exit 1 and `truncated` |
| `unref()`'d timer | ⚠️ | May still fire while the drain confirms idleness: `setInterval(f, 1).unref()` runs `f` 2–3 times before exit; Node exits first. `backlog/runtime-js/node-eval-unref-timer-fires-during-drain` |
| Unhandled rejection whose promise the GC collects before its task ends (an unreferenced rejected promise, then allocation in the same task — a few ms of allocating work, e.g. a `Date.now()` busy-wait, is enough; work that allocates nothing does not trigger it) | ⚠️ | Exit 0, stderr empty (Node: exit 1 with the diagnostic). isolated-vm 7.0.2 keeps the record by weak handle and a GC drops it, so `onUnhandledRejection` never fires; an `unhandledRejection` listener does not fire either. Depends on allocation, not time. No signal tells such a run from a clean exit 0. Avoid it in guest code: handle every promise — end each chain and the async entry point with `.catch((e) => { console.error(e); process.exitCode = 1 })` (set `exitCode` or call `process.exit()`). Same for the README embedder. Upstream https://github.com/laverdet/isolated-vm/issues/589; ceiling rows `reject-*-then-gc`, workaround test in `parity.test.ts`. `backlog/distribution/isolate-host-unhandled-rejection-lost-to-gc` |
| Work already queued when `process.exit()` runs (a microtask of the same checkpoint or one an `'exit'` listener queues, a timer, `setImmediate` or fs callback already due, a timer an `'exit'` listener arms) | ⚠️ | It still runs inside the isolate (Node: nothing runs after `exit()`), but its output is dropped and the status is the exit's, so the result is Node's; a long such job delays the result, an endless one ends as `timeout`, one that allocates past the heap limit as `termination: 'memory'`. At a natural exit the output of the first microtask an `'exit'` listener queues is kept, as in Node; a status change there (`exitCode`, `exit()`, a throw), later hops and a queued `nextTick` do not match Node (row below), and after an `exit()` or throw inside such a listener the earlier-queued microtask still prints (corpus ceiling). The diagnostic of an uncaught throw from queued work still prints after the exit (`queueMicrotask(() => { throw new Error('AFTER') }); process.exit(3)`: `Error: AFTER`, exit 3; Node: empty stderr) — it bypasses the output drop. An exit from a promise callback, `queueMicrotask` or `nextTick` of the synchronous run exits as in Node: corpus `exit-in-*`. `backlog/runtime-js/node-eval-work-queued-at-exit-runs` |
| Work an `'exit'` listener queues at a natural exit | ⚠️ | Node runs it to the end; here only the first microtask hop's output is kept: a `.then` chain or an async listener stops after it, an `exitCode`/`exit()`/throw in any such microtask (the first included) does not change the status (exit 0; a throw prints `Error: …` where Node prints the `[eval]:1` diagnostic and exits 1), and a queued `nextTick` prints where Node runs none. `backlog/distribution/isolate-host-natural-exit-listener-queued-work` |
| Unhandled rejection with other timers pending | ⚠️ | rifty's eval lifecycle fails at the next drain check, not at once, and isolated-vm reports a rejection ~10 ms late: a `.catch` attached from a later task may still run before exit 1 (Node exits first), and an `exit()` among those tasks sets the status, exit 0 included (row "Work already queued"). `backlog/runtime-js/node-eval-unhandled-rejection-timing` |
| `node -e` builtin-module globals (`path`, `fs`, `util`, `crypto`, …) | ✅ | Lazy getters with Node v24.16.0's list; a write replaces them. Corpus `builtin-module-globals`; the guest has every global name `node -e` defines (live list test) |
| `console.log` / `util.inspect` layout | ⚠️ | No line breaking or grouping of long arrays/objects; typed arrays print as objects; default depth 3. `backlog/runtime-js/util-surface-completions` |
| Guest code replacing JS intrinsics rifty's runtime uses (`Promise.prototype.then` and species, `Reflect.get`, `Object.assign`, `Function.prototype.bind`, a throwing `Map.prototype.get`, the array iterator around timer arguments, the runtime's lifecycle slot, …) or forging its exit signal (a `{code:'RIFTY_PROCESS_EXIT'}` lookalike thrown from a timer or microtask, a caught exit signal it mutates) | ⚠️ | rifty's runtime shares the guest's realm without primordials, so the run's status and text can differ from Node's in either direction — exit 0 for a program Node fails included. Open class; measured members are pinned in `packages/isolate-host/tests/guest-seam.test.ts` `BROKEN_RUNTIME`. The guest bundle's tail keeps only the captures that hold measured cases (ADR-0557 §6); what holds regardless is outside the isolate: `runCode` resolves, settles within `timeoutMs` + 1 s, and nothing reaches the host. `backlog/runtime-js/post-guest-paths-use-replaceable-intrinsics`, `backlog/runtime-js/forgeable-process-exit-brand` |
| Work already queued when an uncaught throw or unhandled rejection happens (a timer, microtask, `nextTick` or fs callback; a microtask an `'exit'` listener queues on the fatal) | ⚠️ | Node ends the process at the fatal; here queued callbacks still run and print, and an `exit(n)` among them sets the status — `exit(0)` reads as a clean `{exitCode: 0, stderr: ''}` (an `'exit'` listener still sees 1), `exit(3)` gives 3 — where Node exits 1 with the report. `backlog/runtime-js/node-eval-queued-exit-overrides-pending-fatal` |
| Timer delay outside 1..2^31-1 or NaN | ⚠️ | Runs after 1 ms as in Node, without Node's `Timeout*Warning` on stderr. `backlog/runtime-js/timeout-delay-warnings` |
| Non-function timer callback (`setTimeout(5)`) | ⚠️ | Accepted instead of Node's `ERR_INVALID_ARG_TYPE` (and a BigInt delay's error wins). `backlog/runtime-js/timer-callback-not-validated` |
| Uncaught throw followed by an endless microtask chain | ⚠️ | Ends as `termination: 'timeout'` (Node: exit 1 at once): the isolate never leaves its microtask checkpoint. `backlog/distribution/isolate-host-uncaught-throw-waits-for-microtask-checkpoint` |
| `'exit'` listener setting `process.exitCode` after an uncaught throw | ⚠️ | Exit 1; Node takes the listener's code. `backlog/runtime-js/process-exit-listener-effects` |
| A guest `throw` inside an `'exit'` listener | ⚠️ | Exit 1 with the thrown value reported, without Node's `[eval]:1` source header; Node keeps the status it was exiting with (3 or 5 in the measured cases) |
| A promise rejected inside an `'exit'` listener | ⚠️ | Exit 0, stderr empty (Node: exit 1 with the rejection's diagnostic). Ceiling row `reject-in-exit-listener`. `backlog/distribution/isolate-host-rejection-in-exit-listener-exits-0` |
| Guest-visible runtime global `__rifty` | ⚠️ | rifty's own runtime table (`publishRuntimeGlobal`) is reachable from guest code; it holds no host function, and breaking its own rifty is the guest's business. The host bridge is not reachable |
| `util.inspect` default format: getters, classes, array holes | ⚠️ | Getter printed by value (and called), `class A` as `[Function: A]`, holes as bare commas. `backlog/runtime-js/inspect-default-format-gaps` |
| Uncaught non-`throw` error diagnostic (`undefined.x`) | ⚠️ | No `[eval]:1` source header/caret. `backlog/runtime-js/node-eval-non-throw-diagnostic-header` |
| Uncaught non-`Error` throw (`throw 'oops'`, `throw 5`, `throw {…}`) | ⚠️ | stderr is rifty's fatal text for the value (`oops`, `5`, `[object Object]`), without Node's `[eval]` header, inspect form or `--trace-uncaught` hint; thrown from a timer, async function or `queueMicrotask` it arrives wrapped as `Error: oops` with a bundle frame. `backlog/runtime-js/node-eval-non-error-throw-rendering` |
| `unhandledRejection` listener arguments | ⚠️ | The reason is an isolated-vm copy, and `promise` is `undefined`; a non-`Error` reason arrives as a generic `Error` |
| Identity: `process.version`, `os.platform()`, `process.cwd()` (`/workspace`), `process.argv`, `process.env` (empty), stdin | ⚠️ | rifty's, not the host's |

## Sandbox (`createSandbox`, ADR-0568)

`exec(path, {args})` runs `path` like `node <path> [args]` in `/workspace`. The guest surface and
its gaps are the rows above, except where named here. Tests: `sandbox-acceptance.test.ts` (each run
sequence against live `node <path>` over the same files), `sandbox-faults.test.ts`.

| Surface | Status | Notes |
|---|---|---|
| Run sequences: relative `require`, JSON, `__filename`/`__dirname`, `argv`, `require.main`, relative paths, files the next run reads, only files carrying over | ✅ | Corpus in `sandbox-acceptance.test.ts`; no `node -e` builtin-module globals in a file |
| Host `writeFile`/`readFile`/`list`/`remove`, binary, `/workspace`-relative paths | ✅ | Errors in Node's shape with sandbox paths only; `maxFileBytes`, `maxFsBytes` |
| Endings: exit, `process.exit` (sync, timer, promise callback, `queueMicrotask`), uncaught throw/rejection | ✅ | The files are those the run left |
| Killed run (`timeout`, `memory`) or lost worker | ⚠️ | The files are those of before the run: its writes are rolled back (Node keeps them). A lost worker's run reruns once from the same files |
| Work queued when `process.exit()` runs (a microtask or 0 ms timer beside the exiting one) | ⚠️ | Still runs, and a file it writes is kept (Node: never runs). `backlog/runtime-js/node-eval-work-queued-at-exit-runs` |
| Uncaught throw followed by an endless microtask chain | ⚠️ | `timeout`, its writes rolled back (Node: exit 1 at once, writes kept) |
| A microtask an `'exit'` listener queues, after an explicit `process.exit()` | ⚠️ | Its output is dropped as in Node, but it runs and a file it writes is kept (Node: never runs). `backlog/distribution/isolate-host-natural-exit-listener-queued-work` |
| End state over `maxFsBytes`, too large to capture, or broken by its own guest | ⚠️ | The run's result plus `stateRefused`; files as before the run (Node would fail the write itself, `ENOSPC`) |
| State too large for the run's isolate | ⚠️ | `{stdout: '', stderr: '', exitCode: null, stateRefused: 'ERR_ISOLATE_HOST_SANDBOX_RESTORE'}`; no guest code runs |
| `fs.stat().ino` across runs | ⚠️ | Renumbered at each run's restore (the snapshot keeps the four times, not `ino`, ADR-0567); Node keeps it |
| Text of an uncaught-error report (positions, `file:line` header with caret, `Node.js v…` footer, `SyntaxError` as `ModuleLoadError`, the `Cannot find module` header) | ⚠️ | Error line and file names as Node's; the rest is the runtime-js diagnostics goal's (`node-file-entry-parity`) |
| `import()` of a CommonJS file from a file (top level, async, `eval`, `new Function`, a timer) | ✅ | rifty's loader serves it; corpus row |
| `import()` in source compiled by `vm` | ❌ | The `import()` gap ends the run (exit 1, `isolate-host.dynamic-import`), its writes rolled back: `stateRefused: 'ERR_ISOLATE_HOST_SANDBOX_CAPTURE'` |
| ES modules: `.mjs`, `"type": "module"`, ESM syntax in a typeless `.js` | ❌ | `NotImplementedError('isolate-host.esm')`: rifty's ESM loader needs `URL`, a ceiling here |
| `fs.symlink*`/`link*` | ❌ | `NotImplementedError('fs.<name>')`: rifty's FS has no links (ADR-0050) |
| `exec` options `env`, `cwd`, `stdin`; `createSandbox({ template })` | ❌ | `NotImplementedError('isolate-host.sandbox-exec-<option>')`, `NotImplementedError('isolate-host.sandbox-template')` |

## Custom embedder (`@riftydev/isolate-guest`, ADR-0558)

The same guest bundle in an isolate the consumer creates itself. The guest
surface and its gaps are the rows above. Tests: `packages/isolate-guest/tests/`
(vitest project `isolate-host`).

| Surface | Status | Notes |
|---|---|---|
| Packed export installs and imports with no dependency and no native addon | ✅ | `embedder.test.ts` |
| README example embedder on isolated-vm 7.0.2: parity corpus vs `node -e`; `import()` and uncopyable rejections as `runCode` | ✅ | `embedder.test.ts` |
| Optional `GuestHost.allowSharedArrayBuffer` before loading the bundle | ✅ | Same per-guest policy in the README embedder. `embedder.test.ts` |
| Hostile bridge arguments, throwing embedder hooks, `close()`, `exitStatus` | ✅ | `host-bridge.test.ts` |
| FS snapshot: `GuestEntry.snapshot`/`restore`, `snapshotFs`/`restoreFs` in the isolate and the consumer's realm (ADR-0567) | ✅ | Paths, bytes, empty dirs, names up to 16 383 code units without NUL, `mtime`/`atime`/`ctime`/`birthtime` in the Date range, `readdir` order round-trip, both realms both ways; same tree → same bytes. `snapshot-acceptance.test.ts`, `snapshot-codec.test.ts` |
| FS snapshot: restore that runs out of memory while writing | ⚠️ | `ERR_FS_SNAPSHOT_INCOMPLETE`: the FS is partial; the isolate refuses `run`/`snapshot`/`restore` with that code — dispose it (consumer realm: discard the target) |
| FS snapshot: names over 16 383 code units or with NUL, times not finite or outside the Date range | ❌ | Refused at snapshot (`ERR_FS_SNAPSHOT_UNREPRESENTABLE`) and restore (`ERR_FS_SNAPSHOT_CORRUPT`); rifty's FS holds NUL names and NaN or out-of-range `utimes` values Node refuses or normalises until PR #419 (goal `isolate-host-live-sandbox`) lands — then an honest tree never hits this refusal. Names: V8 hashes longer strings by length alone. A sandbox run that creates such a state cannot save it. Node refuses names over NAME_MAX (`ENAMETOOLONG`); rifty's FS does not yet — `backlog/vfs/file-names-over-name-max-accepted` |
| FS snapshot: `ino` | ⚠️ | Renewed by restore, as after a copy (Node over a persistent disk keeps it): rifty's inode counter is per realm. `backlog/distribution/isolate-host-fs-snapshot-keep-ino` |
| FS snapshot: symlinks, hard links, modes, owners | ❌ | rifty's FS has none (ADR-0050): `fs.symlink*`/`link*` throw `NotImplementedError('fs.<name>')` (ADR-0443 correction 2026-11-22), `chmodSync` is an absent function (`TypeError: … is not a function`), modes are fixed 0o100666/0o40777; nothing of them to keep |
| FS snapshot: restore of untrusted bytes (truncated, flipped byte, bad checksum, other version or template, bad path, duplicate, unknown kind, over `maxBytes`) | ✅ | Named `ERR_FS_SNAPSHOT_*` before anything is written; FS unchanged; no blob text in the error. `snapshot-codec.test.ts` |
| FS snapshot taken after guest code ran | ⚠️ | Guest-authored bytes: the guest can make `snapshot` return anything (it shares the realm); bounded by `memoryLimit`, accepted only through `restoreFs` |
| FS snapshot: restore after `run` was called | ❌ | `ERR_FS_SNAPSHOT_NOT_FRESH`: only a fresh isolate takes a snapshot |
| isolated-vm 6.2.0 | ⚠️ | No `onUnhandledRejection`: an unhandled rejection rejects the embedder's call instead of failing the run with Node's diagnostic — or, after a GC collected the promise, the call settles normally (row "Unhandled rejection whose promise the GC collects"; measured on 7.0.2 without the hook, same code in 6.2.0). No `importModuleDynamically`: `import()` rejects `Not supported` in the guest, and a `.catch` keeps the run alive (it can exit 0) |
| Other V8 embedders | ⚠️ | Untested; the contract (package README §Contract) is embedder-neutral |
| Limits, kill, process boundary, escape posture | ❌ | Not provided by the export; the embedder's duty (package README §What you own) |
| Contract stability | ⚠️ | Unstable: any release may change it |
