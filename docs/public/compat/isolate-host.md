# Isolate host (`@riftydev/isolate-host`, ADR-0557)

`runCode(code)` runs `code` like `node -e <code>` on Node 24. Tests:
`packages/isolate-host/tests/` (vitest project `isolate-host`). The oracle is a live `node -e`
child.

| Surface | Status | Notes |
|---|---|---|
| `{stdout, stderr, exitCode}` of CommonJS `node -e` code | ✅ | Corpus parity `parity.test.ts`: console, byte `process.stdout.write`, UTF-8, `exit`/`exitCode`/`'exit'`, event-loop order, fs on the in-memory VFS, Buffer, path/util/crypto hashes/events, uncaught throw/rejection diagnostics (canonical `[eval]` projection) |
| Fresh instance per call | ✅ | `isolation.test.ts` |
| Limits: time / isolate heap / V8 fatal OOM / child RSS / output cap | ✅ | `termination: 'timeout' \| 'memory'`; RSS is a sampled watchdog that can overshoot by one allocation step; output past the cap is dropped (`truncated`). `limits.test.ts` |
| Network: `fetch`, `WebSocket`, `node:http`/`https`/`net` | ❌ | `NotImplementedError('isolate-host.<api>')`; `node:tls`/`dgram`/`http2` keep rifty's loud stubs. `egress.test.ts` |
| `URL`, `URLSearchParams`, `structuredClone`, web streams, `AbortController`/`AbortSignal`, `Event`/`EventTarget`/`CustomEvent`, `Blob`/`File`, `Request`/`Response`/`Headers`/`FormData`, `MessageChannel`/`MessagePort`/`BroadcastChannel`, web-stream reader/controller/strategy classes, `CloseEvent`/`MessageEvent`, `URLPattern`, `Crypto`/`CryptoKey`/`SubtleCrypto`, `Navigator` and `navigator.*`, `Performance*` classes, `crypto.subtle`, `performance.mark`/`measure`/`nodeTiming`/… | ❌ | `NotImplementedError('isolate-host.<api>')`; successor goal (`docs/ROADMAP.md` M14 B) |
| Static members of those ceiling globals (`AbortSignal.timeout`, `URL.canParse`, `Response.json`, …) | ❌ | `TypeError: … is not a function` — not the named gap; constructing or calling the global itself is |
| `node:zlib`, `node:child_process`, `node:worker_threads` | ❌ | `NotImplementedError('isolate-host.<module>')` at require (rifty builds them on CompressionStream / Workers) |
| Unhandled rejection with a reason isolated-vm cannot copy (function-bearing or null-prototype object, symbol) | ⚠️ | The run fails (exit 1) as in Node; the reason is replaced by `Error: isolate-host: an unhandled rejection reason that cannot be copied out of the isolate` |
| ESM syntax in `-e` (static `import`, top-level `await`) | ❌ | Node 24 detects and runs it as a module; here `NotImplementedError('isolate-host.node-eval-esm')`. `backlog/runtime-js/node-cli-esm-eval-context` |
| `import()` | ❌ | Any form (top level, `await` in an async function, `eval`, `new Function`, a timer) ends the run: stderr gets `Error: Not implemented: isolate-host.dynamic-import (… use require(), ADR-0557)`, exit 1, output produced before it kept. A `.catch` cannot keep the run alive — the gap is reported where the host sees it, since a guest may never observe the rejection. With the output cap already full the gap text is discarded like any output, leaving exit 1 and `truncated` |
| `unref()`'d timer | ⚠️ | May still fire while the drain confirms idleness: `setInterval(f, 1).unref()` runs `f` 2–3 times before exit; Node exits first. `backlog/runtime-js/node-eval-unref-timer-fires-during-drain` |
| Unhandled rejection with other timers pending | ⚠️ | rifty's eval lifecycle fails at the next drain check, not at once, and isolated-vm reports a rejection ~10 ms late: a `.catch` attached from a later task may still run before exit 1 (Node exits first), and an `exit()` among those tasks sets the status, exit 0 included (row "Work already queued"). `backlog/runtime-js/node-eval-unhandled-rejection-timing` |
| `node -e` builtin-module globals (`path`, `fs`, `util`, `crypto`, …) | ✅ | Lazy getters with Node v24.16.0's list; a write replaces them. Corpus `builtin-module-globals`; the guest has every global name `node -e` defines (live list test) |
| `console.log` / `util.inspect` layout | ⚠️ | No line breaking or grouping of long arrays/objects; typed arrays print as objects; default depth 3. `backlog/runtime-js/util-surface-completions` |
| Guest code replacing JS intrinsics rifty's runtime uses (`Promise.prototype.then` and species, `Reflect.get`, `Object.assign`, `Function.prototype.bind`, a throwing `Map.prototype.get`, the array iterator around timer arguments, the runtime's lifecycle slot, …) or forging its exit signal (a `{code:'RIFTY_PROCESS_EXIT'}` lookalike thrown from a timer or microtask, a caught exit signal it mutates) | ⚠️ | rifty's runtime shares the guest's realm without primordials, so the run's status and text can differ from Node's in either direction — exit 0 for a program Node fails included. Open class; measured members are pinned in `packages/isolate-host/tests/guest-seam.test.ts` `BROKEN_RUNTIME`. The guest bundle's tail keeps only the captures that hold measured cases (ADR-0557 §6); what holds regardless is outside the isolate: `runCode` resolves, settles within `timeoutMs` + 1 s, and nothing reaches the host. `backlog/runtime-js/post-guest-paths-use-replaceable-intrinsics`, `backlog/runtime-js/forgeable-process-exit-brand` |
| Work already queued when an uncaught throw or unhandled rejection happens (a timer, microtask, `nextTick` or fs callback) | ⚠️ | Node ends the process at the fatal; here queued callbacks still run and print, and an `exit(n)` among them sets the status — `exit(0)` reads as a clean `{exitCode: 0, stderr: ''}` (an `'exit'` listener still sees 1), `exit(3)` gives 3 — where Node exits 1 with the report. `backlog/runtime-js/node-eval-queued-exit-overrides-pending-fatal` |
| Timer delay outside 1..2^31-1 or NaN | ⚠️ | Runs after 1 ms as in Node, without Node's `Timeout*Warning` on stderr. `backlog/runtime-js/timeout-delay-warnings` |
| Many short intervals at once (e.g. 20000 × `setInterval(f, 1)`) | ⚠️ | Ends as `termination: 'memory'` where Node runs them: host timer ticks queue calls into the isolate with no backpressure. `backlog/distribution/isolate-host-timer-fire-backpressure` |
| Uncaught throw followed by an endless microtask chain | ⚠️ | Ends as `termination: 'timeout'` (Node: exit 1 at once): the isolate never leaves its microtask checkpoint. `backlog/distribution/isolate-host-uncaught-throw-waits-for-microtask-checkpoint` |
| `'exit'` listener setting `process.exitCode` after an uncaught throw | ⚠️ | Exit 1; Node takes the listener's code. `backlog/runtime-js/process-exit-listener-effects` |
| A guest `throw` inside an `'exit'` listener | ⚠️ | Exit 1 with the thrown value reported; Node keeps the status it was exiting with (3 or 5 in the measured cases) |
| Guest-visible runtime global `__rifty` | ⚠️ | rifty's own runtime table (`publishRuntimeGlobal`) is reachable from guest code; it holds no host function, and breaking its own rifty is the guest's business. The host bridge is not reachable |
| `util.inspect` default format: getters, classes, array holes | ⚠️ | Getter printed by value (and called), `class A` as `[Function: A]`, holes as bare commas. `backlog/runtime-js/inspect-default-format-gaps` |
| Uncaught non-`throw` error diagnostic (`undefined.x`) | ⚠️ | No `[eval]:1` source header/caret. `backlog/runtime-js/node-eval-non-throw-diagnostic-header` |
| Uncaught non-`Error` throw (`throw 'oops'`, `throw 5`, `throw {…}`) | ⚠️ | stderr is rifty's fatal text for the value (`oops`, `5`, `[object Object]`), without Node's `[eval]` header, inspect form or `--trace-uncaught` hint; thrown from a timer or async function it arrives wrapped as `Error: oops` with a bundle frame. `backlog/runtime-js/node-eval-non-error-throw-rendering` |
| `unhandledRejection` listener arguments | ⚠️ | The reason is an isolated-vm copy, and `promise` is `undefined`; a non-`Error` reason arrives as a generic `Error` |
| Identity: `process.version`, `os.platform()`, `process.cwd()` (`/workspace`), `process.argv`, `process.env` (empty), stdin | ⚠️ | rifty's, not the host's |
