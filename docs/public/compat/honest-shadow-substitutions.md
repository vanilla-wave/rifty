# Compatibility matrix — honest shadow substitutions

Generated by `pnpm compat:generate` from static inventories backed by conformance and parity tests.

Loud ceilings around the exact synthesized esbuild delegate, lockfile materialization protocol, Workbench owner, and its two Vite runtime adapters (ADR-0296/0298).

Legend: ✅ implemented and tested · ⚠️ partial / known caveat · ❌ not implemented (throws `NotImplementedError` or `UNSUPPORTED_PROTOCOL`).

| Feature | Status | Notes |
|---|---|---|
| Selected esbuild version has no exact substitution recipe | ❌ | Gap `shadow-registry.esbuild@<selected-version>` throws `NotImplementedError('shadow-registry.esbuild@<selected-version>')`. Normal public metadata selection runs first; any selected version other than the one exact generated recipe throws. Explicit user overrides remain ordinary installs. |
| Install requires an asset-readiness owner | ❌ | Gap `npm.install.shadowAssets` throws `NotImplementedError('npm.install.shadowAssets')`. A public install whose exact package tree requires shadow assets must receive the storage-owned installer; tree installation alone never claims runtime readiness. |
| Unknown lockfile materialization marker | ❌ | Gap `npm-client.lockfile.packageMaterialization` throws `NotImplementedError('npm-client.lockfile.packageMaterialization')`. Unknown protocol, kind, or external recipe id is rejected before staging; no marker is accepted by a lossy partial decode. |
| Ambiguous legacy shadow-substitution facts | ❌ | Gap `npm-client.lockfile.shadowSubstitutionFacts` throws `NotImplementedError('npm-client.lockfile.shadowSubstitutionFacts')`. A lockfile that cannot identify one exact top-level shadow trace is rejected instead of inventing provenance. |
| Unknown historical substitution recipe | ❌ | Gap `shadow-registry.substitutionRecipe.<id>` throws `NotImplementedError('shadow-registry.substitutionRecipe.<id>')`. Lockfile trace hydration accepts the append-only recipe inventory only; an unknown id never aliases to the current recipe. |
| Missing Vite esbuild runtime assets | ❌ | Gap `vite.esbuild.shadowAssets` throws `NotImplementedError('vite.esbuild.shadowAssets')`. Both node-entry and direct Vite adapters share the same loud capability ceiling when the exact runtime asset set was not admitted. |
| External Workbench runtime-asset adapter | ❌ | Gap `workbench.runtimeAssets.externalAdapter` throws `NotImplementedError('workbench.runtimeAssets.externalAdapter')`. Workbench v0 owns acquisition through its package source/storage composition; arbitrary host adapter injection is not implemented. |

## Known Limitations

- Only the exact generated esbuild substitution recipe is claimed; unknown versions, marker protocols, recipe ids, and missing adapter capabilities fail loud.
- Direct synthesized esbuild CLI execution is absent rather than a fake binary; the supported consumer is the Vite JavaScript import path after runtime-asset admission.
