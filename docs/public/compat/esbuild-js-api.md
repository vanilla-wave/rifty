# Compatibility matrix — esbuild JavaScript API

Generated by `pnpm compat:generate` from static inventories backed by conformance and parity tests.

COI installs unmodified upstream esbuild-wasm for the requested esbuild range (ADR-0543). Verified against stock esbuild-wasm on Node 24: 0.21.5, 0.25.12, 0.28.2. Other admitted versions: ⚠️ not verified. No generated client or esbuild patches load in COI. No-COI retains the following exact `esbuild-wasm@0.28.0` with `vite@7.3.6` as an integration consumer; Final+GREEN is browser-proven. Every no-COI API row is an exact-version ceiling (⚠️): a request the `esbuild@0.28.0` recipe does not admit is refused at install.

Legend: ✅ implemented and tested · ⚠️ partial / known caveat / exact-version ceiling · ❌ not implemented (throws `NotImplementedError` or `UNSUPPORTED_PROTOCOL`).

## Known Limitations

- COI: esbuild-wasm on Node 24 is the oracle; native-esbuild differences remain visible. A verified version adds only its list entry and upstream archive; the same differential runs in browser-unit CI.
- No-COI: Only exact esbuild 0.28.0 and its exact Vite 7.3.6 integration are in this contract; other esbuild versions stay loud gaps, while Vite 8/Rolldown has an observable empty esbuild plan.
- No-COI: The esbuild CLI is not implemented and throws NotImplementedError('esbuild.cli').
- No-COI: Every D4 gap must preserve upstream validation and error priority before NotImplementedError; a current early, absent, or silent gate is recorded as partial, never supported.
