# Compatibility matrix — Process lifecycle & event loop

Hand-maintained (the `pnpm compat:generate` data-driven sink isn't wired yet). Update by hand after
touching the child-realm drain / keepalive code. Covers how a rifty child process exits — the
event-loop drain model (ADR-0152) and its one deliberate, loud divergence from Node.

A run-to-completion child (`serve` absent/false) exits when its event loop DRAINS (no live refed
handle), like real Node — not at top-level resolve. A long-lived server uses `serve:true` and is
never drain-reaped (kept alive by its own ports). Backing tests:
`tests/e2e/owner-shell-async-lifecycle.spec.ts`, `packages/kernel/tests/worker-entry-drain.test.ts`,
`packages/runtime-js/src/module-loader/loader-keepalive.test.ts`.

| Feature | Status | Notes |
|---|---|---|
| Exit on event-loop drain (not top-level resolve) | ✅ | Post-top-level async (timers, detached `import().then(run)`) completes before reap |
| Keepalive counts `setTimeout`/`setInterval` | ✅ | libuv-style refcount; loop stays alive while a refed timer exists |
| Keepalive counts `setImmediate` | ✅ | |
| Keepalive counts pending dynamic `import()` | ✅ | Both `loader.import` and routed user-code `import()` (`__import`) |
| Unhandled rejection with no listener → stderr + exit 1 | ✅ | Also when the rejection is the program's last work: the drain settles only after one more host task confirms zero refs, so Chromium's later `unhandledrejection` task is seen (ADR-0445 rule 7). The status is final once Chromium reports the rejection: a task that runs after that report and calls `exit(0)` never overrides it on `node <file>`, fork, worker-thread or execSync children (ADR-0445 rule 3). A Node callback already queued before the report runs first (⚠️ row below). Browser-unit `owner-node-process-lifecycle` (`fatal-rejection`, `*-fatal-rejection-then-exit`, `rejection-only-handler`), `event-loop-keepalive-late-rejection.fault.test.ts`, `process-exit-lifecycle.test.ts` |
| `process.on('uncaughtException')` / `'uncaughtExceptionMonitor'` | ✅ | Throws from timers, `setImmediate`, fs/zlib/`util.callbackify` callbacks, `nextTick` and the entry reach the monitor, then the listeners, as `(err, origin)`; the program continues. An ES module entry throw arrives with origin `'unhandledRejection'`. No listener: stderr, `'exit'` 1, status 1. A throwing listener: stderr, status 7, no `'exit'`. Live-Node parity: browser-unit `owner-node-process-lifecycle`, `process/exit-lifecycle-child`, `process/eval-entry-throw-lifecycle`, `process/callback-throw-uncaught-child` (ADR-0445) |
| `process.on('unhandledRejection')` | ✅ | `(reason, promise)` with the promise's identity; the program continues. With no listener the reason goes to `'uncaughtException'` (origin `'unhandledRejection'`), wrapped as Node's `UnhandledPromiseRejection` (`ERR_UNHANDLED_REJECTION`, V8 reason rendering) unless it has an own `stack` (ADR-0445) |
| `'exit'` event | ✅ | Fires once with `exitCode ?? 0` at natural exit (after `-p` prints), on `exit()` and on a fatal error; a listener may set `exitCode`; `exit()` inside a listener skips later listeners and sets the status; timers scheduled in `'exit'` never run. On `node <file>`, `.bin`, spawn/fork, `node -e/-p`, execSync children and worker-thread `exit()` (ADR-0445) |
| **Drain cap: a refed loop that never drains is force-killed** | ⚠️ | **Deliberate non-Node divergence.** At 30 s the worker exits 1 + a self-explanatory stderr line, where Node runs forever. Browser-worker safety-net against a genuine hang/leak — generous + loud. Legit-forever programs use `serve:true` (the cap never fires there). See ADR-0152 §4 |
| Detached `fetch()` / network keepalive | ✅ | The global `fetch` is keepalive-counted: ref on dispatch, held until a public Body consumer drains/cancels/errors (Node keeps the socket refed until the body is read). `http.request` to an external host routes through `fetch` (covered); loopback is in-process; `https`/`net.connect` are loud-throws. A never-consumed body holds the realm to the drain cap (loud). ADR-0158 |
| `Response.clone()` on a keepalive-tracked fetch | ❌ | The public Body wrapper can retain the pre-clone internal stream; later read/cancel may hit a locked stale source instead of Chromium semantics. Explicit draft: `backlog/runtime-js/fetch-keepalive-response-clone-lifecycle`. |
| `WebAssembly.compileStreaming` / `instantiateStreaming` | ❌ | Whole-realm Promise-rejected `NotImplementedError` ceiling for every Response/PromiseLike and argument shape. Native internal-slot body consumption cannot be keepalive-counted without correlation escapes. Effective property + name/length/own descriptors stay native; `Function#toString` exposes the anonymous Proxy (explicit reflection drift). Byte-buffer compile/instantiate remain available. ADR-0158 correction |
| `fs.watch` / `fs.watchFile` keepalive | ✅ | The poll `setInterval` is keepalive-counted; `FSWatcher.ref()`/`.unref()` opt the realm in/out via the poll handle (Node parity) — an unrefed watcher no longer holds the realm to the drain cap |
| Timer `.unref()` / `.ref()` / `.hasRef()` | ✅ | `setTimeout`/`setInterval` handles can opt out of and back into keepalive; `node:timers` uses the same wrapper as globals |
| `MessagePort#ref()` / `.unref()` / `.hasRef()` keepalive | ✅ | A referenced port holds the realm until `unref()` or until either end of its `MessageChannel` pair closes; fresh ports hold nothing. This is the hold emnapi takes for pending napi async work (rolldown wasm32-wasi). The global and `node:worker_threads` `MessageChannel` are one constructor. Live-Node parity in Chromium: `tests/browser-unit/message-port-ref-keepalive.spec.ts`, `tests/browser-unit/message-port-ref-keepalive.fault.spec.ts`. ADR-0447 |
| Referencing moved or received `MessagePort`s | ❌ | Node lets a referenced port, or its peer, be transferred, and lets you `ref()` the kept end or the received copy. Chromium gives no close/detach signal, so rifty could not see that release. `MessagePort#postMessage`, `Worker#postMessage`, global `postMessage` and `structuredClone` throw `NotImplementedError('MessagePort.transfer.referenced')` before anything detaches. `ref()` on the kept end of a split pair, or on a received port, throws `NotImplementedError('MessagePort.ref.transferred')` and `hasRef()` stays `false`. Unreferenced transfers stay native. ADR-0447 |
| `MessagePort` listener referencing | ❌ | In Node a `'message'` listener or `onmessage` refs and starts the port, and removing the last one unrefs it. Rifty listeners never hold the realm, and `hasRef()` reports only manual `ref()`: it is `false` for a listener-held port where Node reports `true`. Messages still queued when the last manual ref drops are not waited for. ADR-0447 |
| `MessagePort` NodeEventTarget methods and `'close'` event | ❌ | `on`, `once`, `off`, `emit`, `addListener`, `removeListener`, `removeAllListeners`, `eventNames`, `listenerCount`, `setMaxListeners`, `getMaxListeners` are absent (`TypeError: port.on is not a function`), and no `'close'` event fires. ADR-0447 |
| `MessagePort#hasRef()` / `ref()` right after `close()` | ⚠️ | Node keeps `hasRef()` `true` (and `ref()` can still set it) until its close-callback phase, also for a port just transferred away. Rifty reports `false` at once. The program ends at the same point. ADR-0447 |
| `MessageChannel` / wrapped method reflection | ⚠️ | `Function.prototype.toString` on `MessageChannel` and on the wrapped `MessagePort#close`/`#postMessage`, `Worker#postMessage`, global `postMessage` and `structuredClone` shows the Proxy/wrapper, not native code. Names, lengths and descriptors stay native. ADR-0447 |
| `process.exit(N)` propagates the exit code | ✅ | Via the `RIFTY_PROCESS_EXIT` shape (ADR-0039); one kernel exit request, a later `exit()` adds none (ADR-0445) |
| `process.exitCode` / `process.exit()` without an argument | ✅ | `exitCode` reads `undefined` until assigned (`null`/`undefined` reset it, `'3'` reads `3`); `exit()` exits with it, `exit(undefined)` resets it to 0 (ADR-0445) |
| `'beforeExit'` event | ❌ | Never emitted (Node emits it when the loop drains). Not on vitest's path |
| `'rejectionHandled'` event | ❌ | Never emitted when a reported rejection gains a handler later |
| `process.setUncaughtExceptionCaptureCallback` / `hasUncaughtExceptionCaptureCallback` | ❌ | Absent members: a call throws `TypeError: … is not a function` |
| `process._exiting` | ❌ | Node's undocumented flag is not exposed (the exit state is internal) |
| Throw from an `'exit'` listener | ⚠️ | Not claimed: Node delivers it to `'uncaughtException'`; rifty does not route it there |
| Worker-thread natural exit (`'exit'` when the loop drains) | ⚠️ | Worker threads claim handler dispatch and explicit `exit()` only; natural exit belongs to `backlog/runtime-js/worker-threads-handle-keepalive` |
| Handler dispatch in no-COI in-process project commands | ⚠️ | Unclaimed (no carrier): they share the realm traps, and their per-invocation exit state (unset `exitCode`, one `'exit'`) is proven (`no-coi-project-command.test.ts`) |
| Fatal throw with an `'exit'` listener that sets `exitCode` | ⚠️ | Node exits with the listener's `exitCode`; a no-listener throw keeps the default Worker report's status 1 (a rejection honours it) |
| Fatal error stderr bytes | ⚠️ | The error and status match; Node's source line, caret and `Node.js v24` trailer are not reproduced |
| `unhandledRejection` vs an already-queued Node callback | ⚠️ | Node processes a rejection before the next timer, immediate or I/O callback. Chromium reports it in its own task, so a callback already queued runs first: a same-turn `setTimeout(0)` or `setImmediate`, a timer ripe at the same time, an fs callback or `fs.promises` result. With a listener only the row order differs. With no listener that callback can print first, and its `exit(0)` exits 0 with no stderr where Node prints the error and exits 1 (ADR-0445 evidence §F2) |
| `node:process` named imports of `cwd`/`chdir`/`hrtime`/`uptime`/`exit`/`kill`/`nextTick`/`exitCode` | ✅ | Own enumerable members with Node's descriptors, so they link as ESM names (ADR-0348 §2; tinyexec/rolldown `import { cwd } from 'node:process'`); detached `exit`/`kill` act on their process. EventEmitter methods and host hooks (`on`, `emit`, `pushStdin`, …) stay link `SyntaxError`s, as Node. Node-own members rifty lacks (`umask`, `cpuUsage`, …) are link-time misses; `kill` beyond `kill(process.pid, 'SIGUSR2')` throws `NotImplementedError`; a self `SIGUSR2` terminates the process even with a live `SIGUSR2` listener (Node runs the listener) — `backlog/runtime-js/process-self-signal-listener`. Known over-export: a non-IPC process still links `send`/`disconnect`/`connected`/`channel`/`_listenersMap`/`_warned` (Node: `SyntaxError`) — `backlog/runtime-js/process-non-ipc-member-over-export`. Parity: `process/esm-named-members`, `process/esm-named-members-off-surface`, `process/unbound-exit-kill` |
| `process.memoryUsage()` / `process.memoryUsage.rss()` | ❌ | Present, every call throws: own enumerable member (+ own `rss`) with Node's descriptor, so `import { memoryUsage } from 'node:process'` links and `process.memoryUsage.bind(process)` works (vitest 4.1.11 pool workers bind it at load). A call throws `NotImplementedError('process.memoryUsage')` / `('process.memoryUsage.rss')` — no browser source for RSS/V8 heap numbers, never a fabricated value; `typeof` feature detection sees a function (ADR-0443). Parity: `modules/builtin-loud-members-link`, `child_process/pool-worker-loud-members` |

## Terminal `node <file>` command (ADR-0155)

The playground terminal runs an arbitrary entry as a supervised child of the workspace owner
(the `.bin`/`runNodeEntry` seam, ADR-0137 — NOT the template dev-server). Server-vs-script is
decided by what the program DOES (it called `listen()`), not a flag — Node-faithful. Backing tests:
`tests/e2e/node-command.spec.ts`, `packages/workbench/src/workers/node-program-lifecycle.test.ts`,
`packages/workbench/src/workers/owner-child-node-executor.test.ts`,
`packages/workbench/src/workers/workbench-project-runtime.test.ts`,
`packages/workbench/src/workers/preview-registry.test.ts`, and
`tests/browser-unit/owner-node-stdio-control.spec.ts`. Run-to-completion loader parity (shebang,
relative `import`/`require`, exit codes) reuses the existing node-entry/resolver conformance
(`packages/runtime-js/src/builtins/node-entry.test.ts`, `tests/conformance/modules/resolver.test.ts`,
`tests/conformance/builtins/child_process.test.ts`) — `node <file>` is the second consumer of an
unchanged loader, so it adds no duplicate parity case.

| Feature | Status | Notes |
|---|---|---|
| `node <file> [args]` run-to-completion | ✅ | Streams stdout/stderr; exits on event-loop drain (the model above) with the program's code; Ctrl-C → exit 130 |
| `./path/to/file [args]` direct Node entry | ⚠️ | A regular VFS file runs through the same supervised Node-entry child; explicit `.bin` paths run launcher targets. Rifty does not model POSIX X_OK or host PATH, so this is a directed Node-entry surface rather than general OS executable dispatch (ADR-0362) |
| `node -e/-p` CommonJS eval context | ✅ | The documented Node 24 spellings, including explicit `--input-type=commonjs`, use the physical supervised child with exact `execArgv`, entryless `argv`, detached `[eval]` identity/cache, cwd-anchored resolution, natural-exit `-p` inspection, ordered stdio/errors, preview, signals, and shell status (ADR-0339–0342). Explicit CommonJS preserves JavaScript `SyntaxError` instead of implicit TypeScript stripping. Differential parity and Chromium acceptance cover sequential and simultaneous children. |
| `node --input-type=module -e/-p` ESM eval context | ❌ | Node v24.16.0 executes `-e` as ESM; Rifty throws `NotImplementedError('workbench.node.eval-module-context')` before allocation and never falls back to CommonJS. Node-invalid print forms already return status 1 with `ERR_EVAL_ESM_CANNOT_PRINT`. Tracked in `backlog/runtime-js/node-cli-esm-eval-context`. |
| Node 24 TypeScript-stripping `node -e/-p` and explicit input types | ❌ | Source requiring implicit TypeScript stripping reaches one physical eval child, then throws `NotImplementedError('runtime-js.node-eval-typescript-context')` in its loader. Explicit `commonjs-typescript`/`module-typescript` forms fail with that gap before allocation; `module-typescript` print forms preserve `ERR_EVAL_ESM_CANNOT_PRINT`. Tracked in `backlog/runtime-js/node-cli-typescript-eval-context`. |
| Node CLI CommonJS preload `--require`/`-r` | ❌ | Node preloads before eval/program execution. Valid Rifty eval and program-entry forms throw `NotImplementedError('workbench.node.preload-context')` before allocation. Omitted arguments and empty inline `--require=` retain exit-9 usage; a separated empty specifier reaches the named gap (Node enters loading and reports `ERR_INVALID_ARG_VALUE`). Tracked in `backlog/runtime-js/node-cli-preload-import-flags`. |
| Node CLI ESM preload `--import` | ❌ | Node imports before eval/program execution. Valid Rifty eval and program-entry forms throw `NotImplementedError('workbench.node.preload-context')` before allocation. An omitted argument and empty inline `--import=` retain exit-9 usage; a separated empty specifier reaches the named gap (Node enters resolution and reports `ERR_MODULE_NOT_FOUND`). Tracked in `backlog/runtime-js/node-cli-preload-import-flags`. |
| Bare `node` interactive REPL | ❌ | Node opens a REPL when stdin is a TTY. Rifty prints `node: missing entry file` plus usage, exits 1, and allocates no child; `-e/-p` does not masquerade as interactive support. Tracked in `backlog/runtime-js/node-cli-bare-repl`. |
| `node -p/--print[=rhs] -- <file>` program transition | ❌ | Node retains the exact print option in program `execArgv`; node-entry v3 programs cannot carry it. Rifty throws `NotImplementedError('workbench.node.print-program-context')` before allocating a child rather than launch with false identity. An empty first token after `--` remains supported entryless eval. See `backlog/runtime-js/node-cli-print-program-context`. |
| `node <server.js>` long-running server | ✅ | A `listen()` keeps the child alive (`serve:true`); the listened port is registered for preview; Ctrl-C stops it |
| Multi-port preview + switcher | ✅ | Each live server (and `npm run dev`) appears in the preview-panel port switcher; routed via `/preview/<port>/` |
| `Error: Cannot find module` for a missing entry (real Node `MODULE_NOT_FOUND`) | ✅ | `node ./nope.js` / `./nope.mjs` emits real Node's multi-line `Error: Cannot find module '<abs>'` + `{ code: 'MODULE_NOT_FOUND', requireStack: [] }`, exit 1 — the loader is the single producer (the owner no longer pre-checks existence), and Node runs a missing entry through its CJS loader for both extensions. The error OBJECT (`err.code` + `err.requireStack` + the `Cannot find module … Require stack:` message) is parity-proven head-to-head for a nested `require()` miss (`tools/node-parity-runner/cases/modules/module-not-found.case.ts`). Honest deltas in the PRINTED form: ALL stack frames are dropped (the `node:internal/…` loader frames have no in-browser equivalent + are version-specific; rifty also doesn't synthesize the user call-site frame Node interleaves on a nested miss), the `Node.js vX` trailer is omitted, `requireStack` uses Node's inline inspect form (long paths don't multi-line-wrap), and a deeper ancestor chain collapses to the immediate requirer. A nested ESM `import()` miss is a DIFFERENT Node error (`ERR_MODULE_NOT_FOUND`) — rifty surfaces an honest non-masquerading `ModuleLoadError` there, not yet that shape: `backlog/runtime-js/esm-import-miss-err-module-not-found` |
| Flowing stdin (`process.stdin.on('data')`) | ⚠️ | The session forwards ordered bytes and explicit EOF to supervised Node/`.bin` children. `pause()`/`resume()`, UTF-8 `setEncoding()`, split-codepoint decoding, and one ordered `end` are real (ADR-0230). Other encodings, pull/readable APIs (`on('readable')`, `read`, `pipe`, async iteration), and raw mode/line discipline remain loud `NotImplementedError` gaps; this is not full `readline`/raw-PTY support. |
| TTY dimensions + live resize | ✅ | Initial `columns`/`rows` and `getWindowSize()` match the run grid. A live xterm resize reaches the same child after logical IPC disconnect, updates stdout/stderr, emits their `resize` events, then `SIGWINCH` in Node order (ADR-0225; real OS-PTY parity + Chromium worker proof). |
| `node x.js &` (trailing background) | ✅ | Runs in a background job via the shell's generic trailing-`&` path; job-control builtins (`jobs`/`fg`/`bg`) are the gap — `backlog/shell/background-job-model` |
| `node:sqlite` (`DatabaseSync`) in a bare `node <file>` | ✅ | Registered for every `node <file>` run; the sql.js engine comes up SYNCHRONOUSLY at the first `require('node:sqlite')` via the realm-installed wasm-bytes provider (no preset flag, no eager 30 s boot — preset-deglue epic) |
| A bare node server reachable from ANOTHER child (loopback) | ❌ | Reachable via `/preview/<port>/` only; cross-realm HTTP loopback is `backlog/net/cross-realm-http-loopback` |

## Recursive `child_process` and nodemon dev loop (ADR-0324–0327)

The claimed surface is the exact installed `nodemon@3.1.14` forcing path, not
general OS process emulation. Node 24 parity covers the primitives; built
Chromium covers the real supervisor → application Worker journey.

| Feature | Status | Notes |
|---|---|---|
| Callable `EventEmitter` legacy construction | ✅ | `new`, subclassing, `EventEmitter.call(target)`, and `util.inherits` share one listener state and prototype identity. |
| Recursive `spawn('node', …)` / `fork()` | ✅ | Each process child is a fresh Worker over the same owner-backed VFS; relative entry, argv, cwd, inherited/replacement env, reads, and writes are parity-proven. Missing launch provenance fails before guest execution; there is no project snapshot or direct-entry fallback. |
| `execFile()` buffered adapter | ⚠️ | Direct argv, cwd/env, encoding/Buffer output, timeout, maxBuffer termination, callback errors, and `util.promisify`'s `{stdout, stderr}` projection match Node 24 over the real `spawn` owner. Browser-unavailable executable/shell carriers retain the spawn ceiling; `shell`, AbortSignal, uid/gid/argv0, and non-SIGTERM timeout signals throw directed `NotImplementedError`s. |
| `spawnSync()` | ❌ | Present, every call throws: own enumerable member with Node's descriptor, so `import { spawnSync } from 'node:child_process'` links (tinyexec 1.3.1). A call throws `NotImplementedError('child_process.spawnSync')` — the only sync child path (`execSync` RPC) carries `node <script>` stdout only, no status/stderr/signal; `typeof` feature detection sees a function (ADR-0443). `execFileSync` stays a link-time miss. Parity: `modules/builtin-loud-members-link` |
| Child stdio and fork IPC | ⚠️ | Claimed `pipe`/`inherit`/`ignore`, explicit process stream targets, fork's single `ipc` slot, final drain, exit-before-close, and default JSON messages work. Numeric extra descriptors, unrestricted inheritance, advanced serialization, handles, callbacks/options, and channel `ref()`/`unref()` throw loudly. |
| PID/PPID tree, `ps`, and signals | ⚠️ | One owner-root ledger covers recursive Workers. Bare `ps`, `ps -A -o ppid,pid`, `SIGUSR2` child kill, and `kill -USR2 <pid>` work for nodemon/pstree; arbitrary formats, other signals, process groups, job control, and `/proc` remain loud gaps. |
| Real nodemon restart loop | ✅ | Express, Hono, and Koa execute pinned installed nodemon. Chromium proves same-port edit/restart; Express additionally proves fresh realm state, rapid-edit convergence, syntax-crash recovery, and Ctrl-C/session-close subtree teardown without resurrection. |
| Public IPC vs private process control | ✅ | Plain spawn has no `process.send`; fork uses logical default-JSON IPC. Listening, port removal, physical exit, peer death, and subtree control stay private and remain live after public disconnect. |

## Known limitations

- The drain cap uses wall-clock (`performance.now()`), so a CPU-busy worker could in principle trip
  the 30 s cap; the cap is generous, so the risk is low.
- The keepalive model is honestly the count of timers/immediates/pending imports + global `fetch`
  + `fs.watch` polls — NOT the full libuv handle set. The reachable network/timer/import surface is
  now covered (rows above); other libuv handle classes are not browser-reachable. ADR-0152 §1 (set
  shape) + ADR-0158 (fetch added).
