# @riftydev/shadow-registry

Consolidated data and strict catalog model for in-browser package substitutions and shims. Typed recipes start in `src/internal/catalog-source.ts`, then `tools/generate-shadow-substitution-catalog.ts` materializes the catalog that npm-client decodes into attested plans. Workbench receives only plan/capability data and owns executable adapters; `src/index.ts` retains shipped override/shim tables. See [ADR-0308](../../docs/adr/npm-client/0308-package-generic-builtin-shadow-substitution-registry-with-optional-runtime-binding.md) for the current contract and [ADR-0015](../../docs/adr/npm-client/0015-shadow-registry-consolidation.md) for the original consolidation.
